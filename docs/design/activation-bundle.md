# 组合激活路径（熟路）

ActivationLink 记住的是「一个知识点管不管用」。

真实问题很少只需要一个知识点。

多数值得反复回答好的问题，答案是靠一组知识点拼出来的——而「这一组知识点作为一个整体反复被用来回答同一类问题」这件事，目前的记忆结构里没有位置存放它。

这篇文档定义补上这个位置的对象：**ActivationBundle（熟路）**。

## 1. 缺口从哪里来

ActivationLink 的身份是「知识点 + 认知视角 + 使用条件」（见 `precompile.md`），链接到的始终是单一知识点。一个需要三块材料才能回答的问题，会稳定地长出三条互相独立的链接。

这带来两个后果：

```text
命中时，三条链接各自命中，反查到三个不同的知识单元；
系统无法判断这三条命中是恰好同时出现的三个不相关结果，
还是历史上就一起构成过同一个答案——两者在链接层面完全无法区分，
稳的做法只能是当作前者处理，退回完整检索重新判断一遍；

学习时，一条链接的信号只反映「这个知识点单独被用得好不好」，
反映不出「这个知识点是不是经常需要和另外几个知识点搭配才管用」；
组合本身反复出现这件事，没有对象在记它、没有分数在累积它，
每次都从零开始重新证明一遍。
```

于是系统面对的实际情况是：**问题越需要综合、越是真实场景里的高价值问题，激活结构反而越帮不上忙**，重新证明一次的成本永远摊在每一次回答上，攒不下来。

这不是 ActivationLink 设计错了，是它天然只覆盖认知结构里的一半——单点管用与否；另一半——组合管用与否，需要一个独立的对象来承载。

## 2. 熟路是什么

熟路是一组知识点在反复回答同一类问题的过程中，逐渐显影出来的稳定组合。

它和 ActivationLink 的关系，类似于「单个词」和「一句常说的话」的关系：单个词各自有含义，但一句常说的话有它自己的、不能拆开单独解释的稳定性——这句话被反复说、被反复听懂，这件事本身值得被记住，不必每次都从单词重新组装。

```text
ActivationLink 回答：这一个知识点，管不管用；
熟路       回答：这一组知识点合在一起，管不管用。
```

熟路不描述知识点之间「是什么关系」（那是 KPN 的职责，见 `kpn.md`），只描述「这几个知识点经常一起被真实问答用到」这一个事实，以及这个事实有多稳固。

熟路的身份是「一类问题 + 一组知识点」，和 ActivationLink 一样，只能在使用中形成，不能在导入或编译阶段预先构造——同一条设计原则在这里同样成立：认知结构来自使用。

## 3. 熟路如何显影

熟路不是被设计出来的，是从已经在发生的问答里被看出来的。

系统已经在记录两件事：一次问答被确信地回答时问的是什么样的问题（场景、目标、对象、约束），以及答案实际依据了哪些知识点。熟路要做的，只是回头看这些记录里反复出现的组合。

```text
把同一类问题的历次问答放在一起看
  （「同一类」的判断标准，与主题识别、复杂度观测使用同一套，
   见 wiki.md、study.md——三处对「同一类问题」必须是同一个答案，
   否则同一批问答会在不同环节里被切成不同的形状）；

看这一类问题历次实际依据的知识点里，
  哪些是几乎每次都出现的（稳定核）——这就是这类问题真正依赖的组合；
  哪些是偶尔出现的（路肩）——这是组合的候补，随后续使用继续观察；

一类问题反复出现的次数不够多、跨越的时间不够长，
  或者「几乎每次都出现」的知识点一个都凑不出来
  ——这类问题暂时没有稳定组合可言，不构成熟路；

稳定核大到失控（几乎所有出现过的知识点都算「稳定」）
  ——说明这不是一类问题，是好几类问题被混在一起看了，
  不该强行合成一条路，而是应该被看作「这类问题需要先被拆开」的信号。
```

熟路和单条 ActivationLink 因此共享同一份原材料——都来自反复发生的真实问答——只是熟路多看一层：不只看「这个知识点单独出现了多少次」，还看「它是不是总和另外几个知识点一起出现」。

## 4. 熟路如何被信任、又如何被修正

熟路和 ActivationLink 一样，不因为第一次显影出来就立刻被信任。但信任不是靠给熟路整体挂一个「候选 → 稳定 → 降权 → 淘汰」的状态标签来表达——那是离散状态机的做法，会在熟路上重犯 `activation-convergence.md` 第 1 节指出的同一个错误：一旦被判定"降权"就退出候选池，也就再也遇不到能把分数拉回来的新证据，状态机图纸上画着的"重新证实"那条箭头，实际上永远走不到。熟路要回答的问题天然拆成两根独立的轴，各自连续打分，而不是共用一个整体状态（完整机制见 `activation-convergence.md` 第 3、6 节）：

```text
触发轴：这一类问题该不该认出这条熟路——
  和 ActivationLink 的观测条件用同一套机制，直接复用，不单独设计：
  第一次显影只是记录一个新观测，这条熟路自己的置信度分布此刻还很宽，
  不足以直接拿来激活，但也不会被排除在外；
  反复被后续问答证实（组合被命中、被真正采用），
  置信度逐渐收窄、抬高，越来越可以直接拿来用；
  开始被真实答案频繁依据但逐渐落空（命中了这组材料，答案却答不上
  或答错）时，置信度相应下修；
  下修之后重新被证实，置信度会再抬回去——这不是"降权、再重新验证、
  再晋升"这样几段式的跳变，是同一条分数随新证据持续移动；
  即使当前置信度不高，也不会被移出候选池，只是分到的试探名额变小，
  长期无人问津时置信度停在低位、很少再被拿去试探，
  但没有一个"淘汰"动作把它彻底抹掉——这正是留住"重新被证实"这条路
  的关键：分数留在池子里，才有机会被新证据推回去；

成员轴：熟路独有，触发轴回答完"该不该认出这条熟路"之后，
  还要回答"这一次到底是哪几个成员在真正撑着这次回答"——
  不再是"核心成员""路肩成员"这种建熟路时定死的标签，而是每个
  成员知识点各自维护一条自己的置信度分布，证据来自熟路每次被用来
  回答问题时"这个成员这次到底有没有真的被引用"（引用=成功，
  没引用=失败），同样用连续打分滚动更新；
  分数过了服务门槛的成员，组装答案时当作必需内容；分数低的，
  可以选择性带上或者不带；持续没被用上分数自然走低，
  持续被用上分数自然走高——不需要一个专门的"晋升核心/降级路肩"
  动作，一个成员此刻算不算核心，只是它此刻的分数落在哪个区间，
  随时可能因为新数据变化。
```

熟路因此始终反映「最近这类问题真实依赖什么」，而不是「第一次被观察到时依赖什么」——这个结论没有变，变的只是它现在由两条连续滚动的分数自然得出，不需要"退核心/补核心""降权/淘汰"这类显式的离散动作去实现它：一条熟路持续被证伪，触发轴的置信度会持续走低，直接服务的机会随之变少，但分数从不被一次性清零或强制移除，也就不存在"一直占着一个错误的捷径"的风险——它能占到的份额，本来就和它当前的置信度成正比。

## 5. 熟路如何被使用

熟路显影出来之后，服务的是同一类问题下一次到来时的识别与激活：一类问题被再次问到，如果它落在某条触发轴置信度已经越过服务门槛的熟路范围内，系统可以直接调用这条熟路已经沉淀出的知识点组合（成员轴分数决定具体带上哪些成员），而不必把「这一类问题该综合哪些材料」重新证明一遍。

这不改变系统原有的谨慎态度：熟路提供的是「这一次该优先看哪些材料」的起点，不是「答案已经确定」的捷径。材料是否真的能撑起这次的具体问题，仍然要经过与单点激活同样的证据核验；熟路只是让系统不必每次都从空白开始搜集材料。

熟路命中之后，系统面对的是「一组经过反复验证、确实经常配合出现的知识点」，而不是临时拼凑起来的几条互不相干的命中——这是熟路和「多条独立命中随手打包」的本质区别：前者是被使用验证过的组合，后者只是巧合。

## 6. 熟路与 ActivationLink：两个粒度，不是替代关系

两者服务的是认知结构里不同的层次，缺一不可：

```text
ActivationLink 回答「这一个知识点值不值得信」——
  单点问题的最短路径，也是熟路本身借以显影的原材料；

熟路           回答「这一组知识点合在一起值不值得信」——
  只有当问题确实需要综合时才会被用到，单点问题不需要它。
```

熟路依赖 ActivationLink 已经在积累的真实使用信号才能显影，不是从零建立一套平行的记忆；ActivationLink 也不会因为熟路的出现而失去意义——一个知识点即使从未进入任何熟路的稳定组合（因为它总是被单独问到），依然应该有机会独立被信任、独立成为后续沉淀的材料。

## 7. 熟路与 Wiki 沉淀

熟路是使用侧显影出来的组合，Wiki 沉淀是材料侧固化下来的表达；两者服务同一个终点——把反复被验证有效的认知固定下来——但熟路不能替代 Wiki 沉淀的任何一个环节。

```text
Wiki 识别哪类问题值得立传，与熟路识别哪类问题存在稳定组合，
  本质上是同一件事——都是在同一批真实问答里寻找反复出现的模式，
  应该共用同一次观察，而不是分别观察两次、各自得出一份可能不一致的结论；

熟路的稳定组合，是「这类问题历史上确实依赖过这些材料」的直接证据，
  比单纯依据词面相似去猜测材料范围更可靠，
  可以作为材料范围判断的补充依据；

一个知识点是否可靠、是否够格进入沉淀，
  除了看它自己的置信度是否已经越过服务门槛，
  也可以参考它是否经常出现在某条触发轴置信度已经很高的稳定组合里、
  且在其中的成员轴分数也不低——
  这是「可靠」的另一种独立证据，不是要放低可靠的标准，
  而是让「反复被间接依赖、但还没轮到单独积累出高置信度」的材料
  不必只因为观测的方式太单一就被判定为不可靠；

沉淀出的页面，最终呈现的仍然只能是已经沉淀完成的正式表达本身，
  不能是未加工的原始材料——熟路提供的是判断沉淀范围和沉淀时机的参考，
  不改变「表达必须经过沉淀这一步，不能绕过」这条底线；

多篇沉淀内容之间的关系是否成立、
  该不该被认可为一个更大的主题，是另一件需要独立核验的事情，
  不因为材料侧显影出一组常用组合就自动被认定成立。
```

## 8. 熟路不是什么

```text
熟路不是知识图谱式的显式语义关系
  （不表达知识点之间「支持」「反驳」「导致」，那是 KPN 的职责）；

熟路不改变材料必须经过表达沉淀才能对外呈现这一底线
  ——熟路提供的是判断依据，不提供绕过表达沉淀本身的捷径；

熟路不是唯一入口
  ——只服务于「问题确实需要综合多个知识点」这一种场景，
  单点问题继续走最短路径，不必绕经熟路；

熟路不是永久结构
  ——它和 ActivationLink 一样，触发轴与成员轴的置信度持续接受真实使用
  的检验，证伪就走低、无人问津就少有机会再被试探，但从不被一次性
  清零或强制移除，不会成为固化的错误捷径。
```

## 9. 总结

知识单元和知识点来自材料；ActivationLink 记住「哪一个知识点管用」；熟路记住「哪一组知识点合在一起管用」。

一句话总结：

```text
真实问题很少只需要一个知识点去回答；
认知结构如果只记得住单点，就永远记不住真正被反复验证过的答案是怎么拼出来的；
熟路把「这一类问题反复依赖哪一组知识点」这件事，
从每次重新证明一遍，变成可以被看见、被信任、也持续被检验的组合记忆。
```
