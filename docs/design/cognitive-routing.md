# 认知路由

知识大脑不应该只有一种处理问题的方式。

问题进入系统后，认知路由只回答一件事：

```text
这个问题是"找东西"还是"想问题"；
如果是想，是读一遍证据就能答，还是需要先组织再推理。
```

据此分为三条路径：

```text
找：  用户要的是材料本身——出处、原文、某内容是否存在。
      定位检索，返回命中内容和来源，不需要理解和综合。

浅想：用户要的是答案，且答案在材料里基本现成，
      只需读懂证据、组织成回答。
      即证据直答：召回 -> Rerank -> 把问题和相关证据交给回答模型，
      回答带出处（见 retrieval.md 证据直答）。

深想：答案在材料里不是现成的，散落多处，需要先组织再推导。
      按知识加工模式实例化 Working Model 槽位，填充证据，
      再按推理模式执行推理。
```

三条路径的成本依次拉开：找几乎不消耗模型，浅想一次模型调用，深想才启动槽位组织和多轮检索。大多数问题应该落在前两条路径上。

路由决策只依赖检索之前就能判断的信息（问题形态）；检索之后才能知道的情况（证据分布、冲突、缺口），由路径内的升级信号和槽位状态承接。

### 复杂度是相对已有知识而言的

不要试图让模型评估「这个问题有多复杂」，也不要为此新增一次分类调用。原因不是成本，而是这个判断本身在系统内不成立。

同一句「什么是 X」：若 X 已经编译出概念页，它是最简单的问题，读一页即可作答；若库里根本没有 X 的材料，它是最复杂的问题，要走完整召回、可能还要外部查证。问题文本一个字都没变，难度却相差一整条链路。

```text
复杂度 = f(问题形态, 系统当前已经沉淀了什么)
```

只读问题文本的分类器只能看到前一项，看不到后一项，所以它的上限很低——它无法知道答案是否已经被预编译好。这就是路由只判断**问题形态**（一个真正属于问题本身、检索前就确定的属性），而把「知识够不够、要不要继续深入」交给检索后的程序信号承接的原因。

由此还可以推出：判断问题形态用查表（规则可读、误配可定位、可被 Study 修正），判断知识是否够用则**只能靠试**——先用代价最低的路径试，用证据本身回答"够不够"，不够再下沉。试探不是设计上的妥协，而是在这个问题上唯一诚实的做法。

### 三种"复杂"分别由谁承接

讨论中容易被混为一谈的三件事，各有不同的归属，不应互相替代：

```text
需要多少知识（几个知识点、跨几个主题）
  → 检索前判断不了，由分层检索的逐层试探与下沉承接
    （Wiki 表达层 → 激活链接 → 补充查找，见 retrieval.md 分层检索路径）；

需要什么推理形式（单点检索 / 比较 / 因果 / 决策 / 多形式组合）
  → 属于问题形态，检索前可判断，就是本节的路由表，
    也是唯一值得做事前判定的一维；

风险与时效要求
  → 与前两者独立，由高风险 Domain 标记与外部证据检索承接。
    高风险问题即使已有 Wiki 页面和 Claim，也不跳过查证
    （见 wiki.md「路径与 Wiki 使用」）。
```

第一维与第二维不能互相代替：一个「哪个更好」的问题即使只涉及两个知识点，也仍然需要比较形式的推理；一个「什么是 X」的问题即使要拼十几个知识点，也不需要升级为决策推理。

"这类问题实际需要多少知识"虽然事前判断不了，却可以事后观测和积累——按问题条件组统计历史上的证据规模、是否被现成结论满足过、是否需要跨主题拼合，正是修正路由映射表的数据基础（聚合口径见 `docs/impl/v1/study.md` 步骤 7「问题复杂度观测量」）。观测量只作为修正映射表的依据，不参与单次问答的在线判定。

## 1. 路由规则

路由复用 Session 已提取的 intent 和 Domain 匹配结果，查表判定，不新增自由分类，不依赖模型对"问题复杂度"的主观评估。

```text
intent ∈ {查出处 / 查原文 / 定位材料 / 确认是否存在}
    → 找

问题形态本身要求组织多方知识（判据见下）
    → 深想（直通）

其余，包括无法判定的
    → 浅想
```

路由表与推理模式的选择共用同一张 intent 映射（见 `reasoning-pattern.md` 第 4 节）：

```text
"如何操作/重启/部署" → procedural
"为什么/什么原因"    → causal
"哪个更好/如何选择"  → comparative
"能否/是否应该"      → decision / deductive
"有什么共性/经验"    → inductive
```

命中映射说明问题可能需要推理，但不直接等于深想：单点的"为什么"经常在材料中有现成解释，先走浅想更便宜。深想直通的判据是保守的，宁可先浅想再升级：

```text
comparative / decision 为主形式的问题；
一个问题组合多个推理形式（如"为什么超支，还该不该继续投入"）；
问题显式要求设计、方案或多因素综合。
```

映射表是可配置规则起步。误配由回答质量信号（Learning Event）暴露，Study 修正映射，而不是每次让模型自由决定。

### 高风险 Domain（可选保护）

如某些 Domain 的回答错误代价明显更高，可在 preset 数据中为该 Domain 标记高风险 flag：命中该 Domain 的问题不走浅想，直通深想，且回答必须出处完备。这是配置层的保护，不是路由的判定维度。

## 2. 升级链：唯一且单向

```text
找 → 浅想 → 深想
```

**找 → 浅想**：定位检索没有字面命中，但存在语义相关内容时，交给浅想组织一段"最接近的内容是什么"的说明，而不是直接返回空结果。

**浅想 → 深想**：由程序信号触发，不由模型自评：

```text
证据分散：Rerank 后的直接证据跨多个章节或多份文档，
  且没有单一片段能覆盖问题主体；
证据冲突：直接证据之间互相矛盾；
浅想弃答：回答模型显式输出"现有证据不足以直接回答"的标记
  （这是浅想输出契约的一部分，作为兜底信号）。
```

升级不是重来：浅想已召回的证据全部带入深想，槽位先用它们填，缺的槽位再定向补召回。升级的代价是"多想"，不是"重找"。

**没有降级**。深想发现问题实际简单，表现为槽位填得快、推理路径短，自然轻量收尾，不需要显式降级规则。

同类问题反复从浅想升级到深想，是路由映射误配的学习信号，应形成 Learning Event，由 Study 修正映射表或将该类问题改为深想直通。

## 3. 深想的内部结构

深想是唯一使用思考框架的路径，四步：

```text
Domain 匹配 → 知识加工模式 KPP（无挂载模式时回退通用默认模板），
              实例化 Working Model 槽位；
intent 映射 → 推理模式 RP（与路由共用同一张表）；
槽位填充    → 槽位定向召回 → Rerank → 证据挖掘 → 填槽，
              维护槽位状态（confirmed / pending / conflict / insufficient）；
推理执行    → RP 按槽位与状态执行，输出结论 + 推理路径，
              出处白名单校验。
```

检索后才能知道的情况，全部由槽位状态承接，不回到路由层重新决策：

```text
insufficient → 定向补召回一轮（受上限约束）；仍空则显式输出缺口，
               保守回答，不编造填充；
conflict     → 不强行裁决，输出条件化的分支结论
               （"若条件 A 则……；若条件 B 则……"）；
外部查证     → insufficient 槽位的补证行为之一，
               针对时效性证据或长期记忆未覆盖的事实。
```

若命中已验证的实践路径（见 `study.md` 第 7 节），可复用其组织方式，跳过从零实例化和填充——这是深想内的快路径；路径失效时回退到通用的 KPP + RP 重新组织。

KPP 与 RP 的定义、选择与约束分别见 `knowledge-processing-pattern.md` 与 `reasoning-pattern.md`；槽位结构与生命周期见 `working-model.md`。

## 4. 处理上限

处理上限是一组固定常量，作为配置而不是每次问题都要做的判断：

```text
KPN 扩展最大跳数；
insufficient 槽位补召回最大轮数；
Working Model 槽位数上限；
深想单问题最大模型调用次数。
```

任一上限耗尽时，停止扩展，基于已有槽位输出保守结论和显式缺口。上限耗尽不是失败，是"当前证据和成本下继续扩散不会提高可靠性"的明确边界。

## 5. ActivationLink 与路径

不同路径对 ActivationLink 的使用要求，按两根独立的轴判断——置信度（连续）和冲突（二元），二者不再挤在同一个状态字段里，各自独立生效（机制见 `activation-convergence.md`）：

```text
找 / 浅想：置信度已越过服务门槛的观测条件参与正式召回，加速定位；
           置信度还没到服务门槛的，不参与正式召回，只占一个小比例的
           试探名额；
深想：     置信度已越过服务门槛的观测条件提供核心知识起点，KPN 补充上下文；
           置信度不足的不得决定推理结构，只能作为探索线索；
           命中的知识点存在 KPN contradicts 关系时，不论置信度高低，
           对应槽位直接标记 conflict（冲突判定是独立于置信度的硬性
           二元门槛，不随置信度打分，版本划分见 docs/impl/）；
           置信度持续走低的链接不作为当前依据，但仍保留在候选池里。
```

ActivationLink 的使用条件四元组为：**场景、目标、推理形式、注意焦点**。推理形式（RP 类型）与路由映射表同源，不引入新判定。

置信度越过服务门槛不是永久生效：若在当前场景反复不适用，新证据会持续把这条使用条件的置信度往下修，而不是在路由层做实时裁决——路由层只读当前分数，不负责调整它。

## 6. 与 Learning Event 的关系

Learning Event 只在产生学习价值时记录：

```text
找 / 浅想：命中失败、用户纠正时记录；
浅想 → 深想升级反复发生于同类问题：记录，供 Study 修正路由映射；
深想：缺口确认、槽位反复空缺、冲突稳定出现、推理路径无效、
      用户纠正时记录；不记录 Working Model 的完整内容。
```

反思不是一条路径。用户纠正、反复失败触发的是 Learning Event，学习由 Study 异步完成，不占用在线问答链路。

## 7. 总结

认知路由把"系统该怎么思考"收敛为一个检索前可判定的选择，加一条检索后有程序信号的升级链。

一句话总结：

```text
先分清是找还是想；想不动了才升级深想；
深想里检索后才知道的一切（缺口、冲突、时效），
都由槽位状态和处理上限承接，不再回到路由层重新决策。
```
