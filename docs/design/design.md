# 知识大脑系统设计

本文档描述如何把 `think.md` 中的总体思想转化为系统设计。

系统的目标不是构建一个静态知识库，而是构建一个能够吸收知识、激活记忆、组织问题、推理、追踪和学习的个人知识大脑。

知识大脑不是通用 Agent 平台，不负责替代 Agent 平台完成任务执行、环境操作和通用工具编排。

知识大脑的目标，是为用户和 Agent 平台提供底层的知识理解、知识使用和知识沉淀能力。

知识大脑也不是知识图谱系统。知识图谱可以作为表达概念、实体和关系的一种方式，但知识大脑的目标不是构建一张完整知识图，而是让知识能够被理解、激活、组织、验证、追踪和沉淀。

整体设计可以概括为：

```text
材料进入
  -> 形成知识单元和知识点
  -> 使用中形成或验证 ActivationLink
  -> 问题触发认知路由（找 / 浅想 / 深想）
  -> 知识加工模式给出领域知识结构和证据槽位（深想）
  -> ActivationLink 激活知识
  -> KPN 在必要时补充上下文
  -> 证据挖掘从知识单元中摘选片段级证据
  -> Working Model 在深想路径中组织思考
  -> 生成回答

如果本次问答产生学习价值：
  -> 形成 Learning Event
  -> Study 根据 Learning Event 调整长期记忆
  -> 稳定结果可编译为 Wiki 页面与可执行主张（Claim）
```

知识大脑不是所有问题都走完整推理链路。查找类问题定位即答；证据现成的问题证据直答；只有答案散落多处、需要组织推导的问题才构建临时认知模型。证据冲突和时效性缺口在深想内由槽位状态和外部补证承接。Wiki 页面是长期沉淀结果，不是导入时一次性生成的产物。

## 1. 系统核心对象

### 原始材料

原始材料是外部知识进入系统时的形态。

它可以是文档、笔记、对话、网页、代码、实践记录或其他信息来源。

原始材料不是最终知识，只是知识大脑的输入。

### 知识单元

知识单元是长期记忆的基础编码单位。

它不是为了检索而切出来的文本片段，而是一个相对完整、可理解、可追溯、可复用的知识表达。

一个好的知识单元应该能回答：

```text
它表达了什么知识；
它来自哪里；
它适合在什么问题中被使用；
它能否回到原始材料取证。
```

### 概念

概念不直接承载知识内容。

概念是认知分类、导航入口和问题理解框架。它的作用是帮助系统理解「当前问题属于哪个认知入口」，而不是直接提供可作答的知识条文。

领域和概念是通用认知定义，提供稳定的分类入口和适用边界；它们不承载视角差异化的激活方式。

### KnowledgePoint

KnowledgePoint 是从 KnowledgeUnit 中抽取或沉淀出的可复用知识表达。

KnowledgePoint 才是可被使用、组合、验证和沉淀的知识内容。它的作用是提供「当前问题可使用的知识内容」，而不是充当认知分类。

KnowledgePoint 不是概念，概念也不是 KnowledgePoint 的别名。概念决定从哪个认知入口进入；KnowledgePoint 提供进入后可供调用的知识表达。

### KnowledgePoint Network

KnowledgePoint Network 是知识点之间的轻量语义连接网络。

它连接的不是文档，也不是主题，而是已经从知识单元中提炼出的 KnowledgePoint。

KPN 的详细设计见 `docs/design/kpn.md`。

KPN 的作用不是检索答案，也不是构建知识图谱。

它的作用是在核心 KnowledgePoint 被 ActivationLink 激活之后，补充 Working Model 所需的上下文，帮助组织变量、边界、反例和知识缺口。

KPN 不应独立扩散：只在核心知识点已被激活、且当前问题需要上下文补充时才启用。KPN 不应替代 ActivationLink，也不应成为新的主题聚类层。

整体定位是：

```text
ActivationLink
    负责找到知识

KnowledgePoint Network
    负责补充上下文

Knowledge Processing Pattern
    负责给出领域知识结构（见 knowledge-processing-pattern.md）

Evidence Mining
    负责摘选证据（见 evidence-mining.md）

Reasoning Pattern
    负责在组织好的结构上执行推理（见 reasoning-pattern.md）

Working Model
    负责组织思考

Learning Event / Trace
    负责记录对长期记忆学习有价值的事件和结果

Study
    负责根据 Learning Event 修正长期记忆
```

### 长期记忆

长期记忆是系统已经吸收和组织过的知识。

它由知识单元、概念、知识点、关系、经验、方法、实践路径和证据来源共同构成。

长期记忆不是一次性完成的结构，而是在使用中逐渐稳定。

其中，知识单元和知识点更偏材料侧和证据侧。

领域和概念更偏使用侧和认知侧，是通用认知定义。

认知视角的差异不体现在领域和概念的定义上，而体现在 ActivationLink 上：同一领域和概念下，不同视角可以形成不同的激活路径和使用条件。

### 认知视角

认知视角描述知识大脑当前如何使用知识。

它可以来自：

```text
使用者；
角色；
任务类型；
专业方向；
长期使用环境。
```

例如：

```text
采购管理；
软件架构；
售前投标；
项目管理；
个人学习。
```

### Domain / Concept 与 ActivationLink 的职责边界

领域和概念是通用定义，不承载视角差异化的使用方式：

```text
名称、描述、适用边界等描述稳定的认知入口和分类框架；
回答「这个知识点可能属于哪个认知分类」；
不表达「在某个视角、场景、目标下如何激活某条知识点」。
```

认知视角的差异只体现在 ActivationLink 上：

```text
同一领域和概念下，不同认知视角可以有不同的激活路径；
场景、目标、推理形式、注意焦点等使用条件属于 ActivationLink；
同一知识单元在不同视角下可以有不同的 ActivationLink，或仅有部分视角建立了激活路径。
```

因此，领域和概念应在当前认知视角下被查询和使用，但其语义本身是共享的；视角差异通过 ActivationLink 沉淀。

### 知识结构

知识结构描述长期记忆内部如何组织。

它包括：

```text
领域；
概念；
知识点；
关系；
方法；
经验；
实践路径；
待验证假设。
```

知识结构的作用，是让系统面对问题时能够激活相关记忆，而不是从文本中盲目搜索。

知识结构可以包含图状关系，但不等同于知识图谱。

它服务于知识使用，而不是为了构建一张完整静态图。

第一版中的关系主要承担证据、溯源、索引、激活记录和使用记录，不承担开放知识图谱推理。

### 认知路由与路径

认知路由描述系统面对当前问题时走哪条处理路径。

不同问题不应该都走同一条深度推理链路。

系统根据问题形态（intent 查表）把问题路由到三条路径之一：找（定位检索）、浅想（证据直答）、深想（按知识加工模式组织槽位、按推理模式推导）。路径可沿"找 -> 浅想 -> 深想"单向升级，升级由程序信号触发。详见 `cognitive-routing.md`。

路径不是单个模型提示词，也不是某个检索函数。

它应该落地为一类可以被系统选择和执行的问题处理过程。

在工程实现中，路径由 agent 承载。

Agent 负责按照当前路径编排多个认知服务，完成一次问题处理。

### 认知能力

认知能力描述知识大脑为了理解、检索、组织、推理、追踪和学习而具备的稳定能力。

例如：

```text
问题理解；
认知结构激活；
材料补充查找；
检索结果融合；
缺口识别；
证据回溯；
临时认知建模；
推理组织；
学习事件记录；
学习沉淀。
```

认知能力不应该直接等同于模型可见的 skill。

它更像系统内部稳定服务。

在工程实现中，认知能力应落地为 service。

Service 负责稳定的数据访问、索引查询、模型调用、错误处理、状态记录和 trace 输出。

模型提示词只参与 service 内部需要语义判断的局部步骤。

因此：

```text
认知能力 -> service；
路径 -> agent；
agent 编排 service；
service 在必要时调用模型提示词。
```

### 临时认知模型

临时认知模型是系统围绕本次问题建立的工作模型。

它不是长期记忆，也不是最终回答。

它负责把本次问题相关的概念、知识、证据、缺口、冲突和推理路径组织起来，让系统可以在此基础上思考。

### Learning Event / Trace

Learning Event 是问题处理后产生的学习事件。

Trace 是 Learning Event 的记录形式，详见 `docs/design/trace.md`。

它只记录对长期记忆有价值的事件和结果，不记录完整思考过程。例如：激活路径是否成功、是否存在认知缺口、用户是否纠正、是否发现知识冲突、是否观测到新的 ActivationLink 使用条件、是否需要调整 Concept 或 Wiki、是否需要重新验证某个 KnowledgePoint。

边界说明：

```text
Trace 不是每次问题处理的必经步骤；
Trace 不记录完整思考过程；
Trace 不保存模型推理链；
Trace 只记录学习相关事件；
Study 服务于长期记忆优化，尤其是 ActivationLink；
复盘和反思能力属于 Agent Runtime，不属于 Knowledge Brain 的核心职责。
```

### 学习结果

学习结果是 Study 根据 Learning Event 对长期记忆做出的调整。

它可以强化一个知识点，修正一条关系，补充一个概念，沉淀一条实践路径，或者标记一个知识缺口。

学习结果分属材料层、认知层和表达层。材料层调整知识单元和证据可靠性；认知层调整领域、概念和 ActivationLink；表达层判断哪些主题已足够稳定，适合编译或更新 Wiki 页面。

### 可执行主张（Claim）

可执行主张是表达层编译产出的结构化稳定结论，是 Wiki 页面的同源机器可读形态。

一条 Claim 至少包含：结论内容、依据的 KnowledgePoint 与来源证据、成立前提、待验证或冲突标记、版本与时效信息。置信度与时效复用生命周期状态和使用统计，冲突复用 KPN 的 contradicts 关系，不重复建模。

Claim 只能由 Wiki 编译产生，与页面共享证据白名单和版本，随重编译一起演化，不可独立编辑。它不是第二份知识库，而是稳定知识的可执行投影：深想路径的槽位可以直接消费 Claim（经程序校验回链），不必从页面文本中临场解析结论。

详见 `wiki.md`。

### Wiki 页面

Wiki 页面是知识大脑在长期使用中逐渐稳定出的主题性知识表达。

它不是原始材料，也不是导入时一次性生成的目录摘要，而是材料层和认知层经过反复激活、验证和反馈后，在表达层编译出的可读、可维护、可演化的长期沉淀。

同一次编译同时产出 Wiki 页面（面向人）与 Claim 集合（面向程序），二者同源同版本；页面是 Claim 集合的可读投影，不是另一份独立维护的知识副本。

同一批知识单元在不同认知视角下，可以形成不同的 Wiki 页面。

### 知识表达的分层

从材料到认知系统，知识表达分为五层，各层职责不同、不可互相替代：

```text
KnowledgeUnit：  材料侧最小完整知识包，负责可追溯——一切结论最终回到它取证；
KnowledgePoint： 从知识单元提炼的可激活断言，负责可激活——检索、KPN 连接
                 和槽位填充的基本单位；
ActivationLink： 使用中沉淀的激活路径，负责何时调用——从任务条件指向知识点
                 及其建议用途；
Claim：          编译产出的可执行主张，负责稳定复用——带前提、证据与冲突
                 标记的结构化结论；
Wiki 页面：      Claim 集合的可读投影，负责长期阅读与维护。
```

对认知系统（认知路由、Working Model、推理模式）而言，各层的消费规则是：

```text
找 / 浅想可以直接引用置信度已越过服务门槛的链接与稳定 Claim，并携带回链；
深想的槽位以片段级证据为主要填充物，Claim 是候选之一而非唯一依据；
高风险、高冲突、高时效问题必须回到 KnowledgePoint / KnowledgeUnit 层取证，
  不得只停留在 Claim 或页面层；
任何进入回答的内容都必须能沿 Claim -> KnowledgePoint -> KnowledgeUnit -> 来源
  回链，断链的内容不得进入回答。
```

## 2. 知识如何进入长期记忆

外部材料进入系统后，不应直接成为可使用知识。

它需要先被转换为规范化 Markdown，并保留来源上下文，然后再进入从材料到长期记忆的过程。

### 保留来源

系统首先要保留材料来源。

知识大脑不是凭空记忆，它必须知道每个知识来自哪里。

来源保留的目的不是工程追踪，而是为了让未来回答可以回到证据，并让旧知识在材料变化后可以重新判断。

### 形成知识单元

系统需要把原始材料转换为知识单元。

知识单元的目标不是越短越好，而是表达一个完整的认知动作。

例如：

```text
一个定义；
一个判断；
一个原则；
一个约束；
一种方法；
一个案例；
一个经验。
```

知识单元是长期记忆的最小可用表达。

### 形成初始激活结构

知识单元仍然是局部知识。

系统可以从知识单元中形成轻量的初始激活结构。

它不是完整知识体系，也不是最终 知识结构。

它主要包括：

```text
知识单元中的可激活知识点；
可能匹配的已有领域；
可能匹配的已有概念；
候选领域和候选概念；
来源、证据和使用线索。
```

领域和概念不应该仅因为导入了一篇文档就稳定生成。

它们更多是在真实问题处理中被反复激活、使用、验证和反馈后逐渐稳定下来。

领域和概念是通用定义，其边界调整来自长期观察；认知视角的差异主要体现在使用过程中形成的 ActivationLink 上。同一批材料，在不同使用者、任务类型和问题场景下，可以形成不同的激活路径和实践沉淀，而不是各自长出完全不同的领域和概念体系。

因此，知识体系不是从导入文件时一次性建立，而是在使用中逐渐长出来。

ActivationLink 也不应在导入阶段稳定生成。它是在真实问题处理中，根据问题主题、认知视角和反馈逐渐形成的认知连接，让相关知识点可以被快速激活，并通过知识点反查知识单元和来源。Wiki 页面同样来自长期使用中的稳定主题，而不是导入时的直接产物。

## 3. 问题如何被处理

当用户提出问题时，系统不应该直接检索文档并生成回答。

它也不应该无论什么问题都进入完整推理链路。

它应该先经认知路由确定问题走哪条路径，再按对应方式处理。

### 理解问题

系统首先判断问题是什么。

它需要识别：

```text
问题领域；
问题类型；
核心概念；
用户意图；
需要的回答形态；
是否需要外部证据。
```

问题理解决定后续激活哪些长期记忆。

### 认知路由

理解问题之后，系统按问题形态把问题路由到三条路径之一：

```text
找：  定位检索，返回命中内容和来源；
浅想：证据直答，把召回并经 Rerank 分类后的相关证据交给回答模型；
深想：按知识加工模式组织 Working Model 槽位，按推理模式推导。
```

路由决定后续是否需要激活长期记忆、查找外部证据、组织临时认知模型。路径沿"找 -> 浅想 -> 深想"单向升级，升级由程序信号触发（无字面命中、证据分散、证据冲突、浅想弃答）。证据冲突和时效性缺口在深想内由槽位状态和外部补证承接；回答失败或用户纠正经 Learning Event 交给 Study。详见 `cognitive-routing.md`。

### 分层检索与激活

激活长期记忆不是单一路径，而是分层展开。

系统优先沿使用中形成的 ActivationLink 激活知识点，并通过知识点反查知识单元和来源。当正式激活路径不足时，再依次借助材料目录结构树、全文检索或相近表达检索进行补充；当前知识不足、可能过期或风险较高时，再查找外部证据。

各层召回的结果不应按来源层级简单排序，而应统一比较相关性、证据质量、问题目标、历史使用效果和可追溯性，再决定采用哪些知识进入回答。

### 激活长期记忆

系统根据问题和所在路径激活相关知识。

激活不是全文搜索，而是沿着领域、概念、关系、经验和实践路径进行联想。

系统应该优先调用已经形成的长期知识结构。

### 判断知识缺口

系统需要判断已有知识是否足够。

它应该能区分：

```text
可以直接回答的部分；
需要证据确认的部分；
当前知识中缺失的部分；
存在冲突或不确定的部分。
```

这是系统的元认知能力。

### 查找外部证据

当长期记忆不足时，系统应查找外部证据。

外部查找不是随机搜索，而是由当前问题和知识缺口驱动。

它的目标是验证假设、补充事实、确认边界或发现反证。

### 组织临时认知模型

只有深想路径才构建临时认知模型。

当问题形态直通深想，或浅想路径的升级信号触发（证据分散、证据冲突、浅想弃答）时，系统把激活的长期记忆和查找到的外部证据组织成本次问题的临时认知模型，并按知识加工模式和推理模式组织推理。

这个模型应该包含：

```text
当前问题；
核心变量；
相关知识；
已知事实；
缺失信息；
支持证据；
反对证据；
可能推理路径；
回答边界。
```

临时认知模型是回答生成前的关键中间层。

### 推理与回答

系统基于临时认知模型完成推理。

推理过程中需要检查：

```text
结论是否有证据支撑；
关系是否成立；
是否存在冲突；
是否需要表达不确定性；
回答是否解决用户问题。
```

最终回答是当前认知条件下的最优输出，而不是绝对真理。

## 4. 学习事件与长期记忆调整

Knowledge Brain 不追求保存每次问题处理的完整思考过程。

系统只在出现学习价值时记录 Learning Event。没有学习价值的问题处理，可以不生成 Trace，也不阻塞回答流程。

**有效学习不依赖用户持续纠正。** 主学习燃料来自每次问答中自然产生的检索事件：`activation_success`（路径命中且知识被采用）、`activation_failure`（路径命中但未支撑有效回答）、`activation_gap`（无合适路径但补充查找找到被采用的知识）。这些事件自动产生；Study 通过跨次累积（`repeated_success` / `repeated_failure`）持续校准每条 ActivationLink 使用条件自己的置信度，使其分布逐渐收窄（机制见 `activation-convergence.md`）。`user_correction` 是高价值补充信号，可加速边界修正，但不是演化的前提。详见 `study.md` 第 2 节与 `trace.md`。

Learning Event 关注的事实信号包括：

```text
【检索事件——主驱动】
激活路径是否成功或被采用（activation_success）；
激活路径是否命中但失败（activation_failure）；
是否存在激活路径缺口且补充结果被采用（activation_gap）；
同类条件下是否反复成功或失败（repeated_success / repeated_failure）；

【其他学习信号】
是否存在认知缺口或知识冲突；
是否有候选 ActivationLink 值得观察；
是否需要调整 Concept 或 Wiki；
是否需要重新验证某个 KnowledgePoint；

【用户反馈——补充加速】
是否出现用户纠正（user_correction）。
```

Study 根据 Learning Event 调整长期记忆，尤其是持续校准 ActivationLink 每条使用条件的置信度、新增观测；在结构信号足够稳定时，也可提炼候选实践路径，作为深想内可复用的快路径。详见 `study.md`。

完整复盘——例如为什么一次任务失败、如何改进行动策略——属于 Agent Runtime，不属于 Knowledge Brain 的核心职责。

## 5. 知识如何学习和演化

知识大脑必须从使用中学习。

每一次问题处理都会暴露长期记忆的状态——**主要通过检索与采用事实**，而不依赖用户是否纠正：

```text
哪些 ActivationLink 被召回、是否被实际采用；
哪些路径支撑了有效回答，哪些命中后仍失败；
哪些问题只能通过补充查找回答，暴露了激活缺口；
哪些知识真正参与推理；
哪些问题暴露材料或认知缺口。
```

系统应根据这些检索事件及其累积调整长期记忆。用户反馈可以加速修正，但不是学习的必要条件。

### 强化

被反复验证有效的知识点、ActivationLink 和实践路径，应该被强化。

实践路径的强化通常来自另一条链路：深想路径下某类问题的组织方式在多次 Learning Event 中被证明稳定有效（例如 activation_success 反复触发、核心变量组合高度相似），Study 将其提炼为候选实践路径，经独立验证后成为深想内可复用的快路径。详见 `study.md` 第 7 节。

### 修正

导致错误理解或错误回答的知识、ActivationLink 或推理路径，应该被修正。

### 补充

反复暴露的缺口，应该成为新知识输入或新学习任务。

### 重组

当旧的知识结构无法解释新的问题模式时，系统应该允许知识结构重组。

### Wiki 编译

当某个主题在材料层和认知层都已足够稳定，表达层应将其编译为 Wiki 页面与同源的 Claim 集合，或在已有页面上补充、重组和更新。Wiki 编译是学习的结果，不是导入的副产品。

知识演化不是异常流程，而是知识大脑持续成长的正常方式。

## 6. 生命周期与记忆有效性

长期记忆不是永远有效。

知识可能会过期、被修正、被替代或失去上下文。

因此，系统需要管理记忆有效性。

当前回答应该优先使用有效、稳定、可追溯的知识。

旧知识可以保留，用于解释历史思考和知识演化，但不应该默认作为当前答案依据。

生命周期管理在知识大脑中相当于记忆的有效性判断机制。知识状态只需要 current、superseded、deprecated 三种——当前有效的、被新版本替代的、来源被删除的——就足以覆盖知识从产生到失效的完整过程，不需要 candidate/needs_verification/conflicted/historical/retracted 这类更细的中间状态（详见 `lifecycle.md` 第 2 节的场景倒推）。

## 7. 认知稳定性与质量控制

知识大脑不仅要能吸收和使用知识，还要防止错误路径、临时思考和过期结论被误当作长期真理。

系统在多个层面需要质量控制：

**ActivationLink 需要持续被证据校准置信度**

链接不是「被使用过」就会自动稳定。每条使用条件各自维护一条连续的置信度分布，而不是共享链接整体的一个状态标签（机制见 `activation-convergence.md`）：置信度不足的只能辅助探索，越过服务门槛的也需要持续校验，命中 KPN contradicts 关系覆盖的知识点时不应作为当前首选依据。Study 的目标是让高置信度的使用条件更少、更准，而不是让链接数量无限增长。

**认知路由需要由程序信号约束**

路由基于问题形态查表判定，升级由程序信号触发（无字面命中、证据分散、证据冲突、浅想弃答），而不是完全依赖模型主观判断。查找和证据现成的问题轻量处理，需要组织推导的问题才进入 Working Model；证据冲突由槽位状态承接，时效性缺口由外部补证承接。

**Working Model 需要质量检查**

临时认知模型在输出前应检查问题边界、变量完整性、证据覆盖、缺口显式性、正反证据并存、推理可回溯性，以及回答边界是否与证据强度匹配。Working Model 是一次性思考结构，不能直接沉淀为长期记忆。

**知识生命周期需要区分当前、替代、废弃**

长期记忆应区分 current、superseded、deprecated 三种状态。current 也不是永久状态，会因为来源更新或删除而让位；superseded 和 deprecated 都保留数据用于追溯，不代表错误，只代表"不再是当前依据"。知识之间的冲突由 KPN 的 contradicts 关系在检索时动态呈现（见 `unit.md` / `retrieval.md`），不需要单独的冲突状态。

**Wiki 编译需要防止长期结论固化**

Wiki 页面是当前阶段的稳定表达，不是最终真理。页面应保留适用边界、争议点、待验证点、证据来源和修订记录；新证据和底层状态变化应触发重新编译，冲突知识不能被强行合并成单一结论。

## 处理上限

知识大脑不应对所有问题都执行完整认知流程，也不应允许深想路径无限扩展。

处理深度首先由认知路由决定：找和浅想不构建 Working Model、不扩展 KPN；深想才启动完整组织。

深想内部由一组固定上限常量约束：

```text
KPN 扩展最大跳数；
insufficient 槽位补召回最大轮数；
Working Model 槽位数上限；
深想单问题最大模型调用次数。
```

上限是配置，不是需要每次判断的决策。任一上限耗尽时，停止扩展，基于已有槽位输出保守结论和显式缺口，而不是继续扩散 KPN 或堆叠推理步骤。详见 `cognitive-routing.md` 第 4 节。

## 8. Agent 如何使用知识大脑

Agent 平台和知识大脑的职责不同。

Agent 平台负责执行任务。

知识大脑负责提供知识、证据、思考框架、临时认知模型、学习事件记录和学习沉淀。

因此，Agent 不应该直接访问整个知识仓库，也不应该把知识大脑当成一个普通 RAG 工具。

它应该在明确领域边界内调用知识大脑能力。

知识大脑可以为 Agent 提供：

```text
领域长期记忆；
相关知识激活；
来源证据；
认知路由；
临时认知模型；
冲突与缺口的显式呈现；
Learning Event 记录；
经验沉淀和学习建议。
```

Agent 使用知识时，也应该经历类似过程：

```text
理解任务；
认知路由；
激活领域记忆；
判断缺口；
必要时组织临时认知模型；
推理执行；
若产生学习价值则形成 Learning Event；
反馈学习。
```

Agent 不是知识系统之外的消费者，而是知识大脑的一种实践入口。

Agent 的使用结果也应该反哺长期记忆。

但知识大脑不负责 Agent 平台本身的通用能力，例如：

```text
任务调度；
工具运行时；
浏览器或终端操作；
代码编辑执行；
多 Agent 协作协议；
权限和沙箱管理。
```

这些能力属于 Agent 平台。

知识大脑只关注知识如何被这些任务使用，以及使用之后如何被追踪、评估和沉淀。

## 9. 能力对应关系

系统可以按认知能力组织。

```text
外部材料进入系统；
材料被整理成可追溯的知识单元和知识点；
使用中形成候选 ActivationLink；
问题经认知路由分流（找 / 浅想轻量处理，深想进入 Working Model）；
优先沿 ActivationLink 激活记忆，不足时分层补充查找；
必要时组织临时认知模型；
若产生学习价值则形成 Learning Event，Study 调整长期记忆；
长期稳定的主题编译为 Wiki 页面；
长期记忆的状态和有效性被持续管理。
```

这些能力不是孤立工具，而是知识大脑认知链路中的不同部分。

实现时应避免把认知能力直接做成由模型自由调用的 skill。

认知能力涉及知识库、索引、状态、证据、错误处理和学习事件记录，应该由稳定 service 承载。

Agent 根据当前路径编排这些 service。

模型只在需要语义判断、摘要、匹配或推理时，作为 service 内部步骤被调用。

## 10. 总结

系统设计的核心不是“文档如何检索”，而是“知识如何被一个持续学习的认知系统使用”。

整体链路是：

```text
材料进入
  -> 形成知识单元和知识点
  -> 使用中形成或验证 ActivationLink
  -> 问题触发认知路由（找 / 浅想 / 深想）
  -> ActivationLink 激活知识，不足时分层补充查找
  -> KPN 在必要时补充上下文
  -> Working Model 在深想路径中组织思考
  -> 生成回答

如果本次问答产生学习价值：
  -> 形成 Learning Event
  -> Study 根据 Learning Event 调整长期记忆
  -> 稳定结果可编译为 Wiki 页面与可执行主张（Claim）
  -> 长期记忆和认知结构持续演化
```

这就是知识大脑系统的基本设计。
