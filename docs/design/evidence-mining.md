# 证据挖掘

知识单元是主题单位，证据是回答单位。二者不是同一粒度。

检索和 Rerank 完成后，系统得到的是"与问题相关的知识单元"。但知识单元是一个完整主题，其中真正回答问题的往往只是几句话、几个步骤、一条命令或一张表的几行。

如果不做区分，回答环节面对的就不是证据，而是一批"相关段落"。

证据挖掘（Evidence Mining）负责补上这一层：

```text
知识单元回答"哪些主题与问题相关"；
证据挖掘回答"这些主题中，哪些内容真正支撑答案"。
```

## 1. 为什么需要证据挖掘

以"如何重启集群"为例。相关知识单元可能是一篇完整的部署文档章节，其中混写着安装、配置、初始化、停止、启动、验证等内容。

真正需要的证据是：

```text
✓ 停止集群的步骤
✓ 启动集群的步骤
✓ 验证集群状态的方法
✗ 创建数据库
✗ 修改配置
✗ 初始化环境
```

如果整个知识单元原样进入回答环节，会产生四类问题：

```text
噪声干扰：无关内容与证据混在一起，回答模型需要自己分辨，
  分辨失败就产生答非所问或引入无关步骤；
引用粗糙：引用只能指向整个知识单元，无法说明"答案依据的是哪句话"；
上下文浪费：多个知识单元的完整正文很快耗尽上下文，
  真正的证据被淹没在背景描述中；
学习信号模糊：追溯和学习只能观察到"这个主题被用了"，
  无法观察到"主题中哪部分内容被采用"。
```

对能力有限的模型，第一类问题尤其严重。让模型在几十段混杂文本中边分辨边推理边组织答案，是多任务叠加；把分辨这一步单独拆出来，每一步都变成窄任务。

## 2. 挖掘什么，产出什么

证据挖掘的输入是 Rerank 分类后保留的知识单元，输出是从这些知识单元正文中摘选出的证据片段。

一条证据片段是知识单元正文中**最小且充分**的一段原文：

```text
一句陈述；
一组步骤；
一条命令；
一段规则；
表格中的若干行。
```

最小，指不携带与回答无关的上下文；充分，指脱离知识单元其余内容后仍能独立表达该证据的含义。二者冲突时以充分为先——宁可多带一句，不可摘出歧义。

每条片段必须保留回到来源的能力：它属于哪个知识单元、位于原文什么位置。片段是知识单元的子区间，不是脱离来源的新文本。

## 3. 逐字摘录，程序可校验

证据挖掘的核心原则是：**挖掘是摘选，不是改写**。

摘出的片段必须与知识单元原文逐字一致。这带来一个关键性质：程序可以用原文匹配来校验挖掘结果，凡是在原文中找不到的"证据"，都是幻构，直接拒绝。

这个原则的价值在于：

```text
幻觉被程序拦截，而不是靠模型自觉；
片段可以精确定位回原文位置，追溯链自然成立；
挖掘退化为"从文本中标注区间"这类窄任务，
  小模型也能稳定完成，且结果可验证。
```

这与引用校验是同一设计思想的延续：模型的自由输出永远经过程序的白名单校验，校验依据来自系统已有的确定事实（原文、已分配的证据标识），而不是模型的另一次判断。

校验失败的处理原则：

```text
个别片段匹配失败：重试或丢弃该片段，不影响其余片段；
整个知识单元挖掘失败：回退为整段证据进入后续环节，
  并标记"未挖掘"——回退保证回答不中断，标记保证退化可被观察。
```

## 4. 在流程中的位置

证据挖掘位于 Rerank 之后、证据被消费之前：

```text
多路召回
  -> Rerank（逐条分类：直接证据 / 支持性证据 / 无关）
  -> 证据挖掘（片段级摘选）
  -> 证据直答，或按知识加工模式槽位进入 Working Model
```

Rerank 与证据挖掘的分工是：

```text
Rerank 判断"这个知识单元与问题是什么关系"，粒度是知识单元；
证据挖掘判断"这个知识单元中哪些内容支撑回答"，粒度是片段。
```

挖掘的目标由问题决定。若本次问题已识别出知识加工模式（见 `knowledge-processing-pattern.md`），挖掘按模式的证据槽位定向摘选——为每个槽位寻找对应片段；若没有模式，则按问题本身摘选。前者让挖掘有明确的结构目标，是更强的工作方式。

证据挖掘只能加工已经召回的内容。它不解决"该召回的没召回"——那是检索和知识加工模式驱动的召回扩展的职责。

## 5. 对追溯和学习的价值

证据粒度细化后，下游环节同步受益。

**引用更精确**。答案的每个论断可以指向具体片段，而不是整个知识单元。用户看到的是"依据这句话"，而不是"依据这一章"。

**学习信号更精确**。追溯和学习原本只能观察"哪个知识单元被采用"；现在可以观察"知识单元中哪部分内容被反复采用、哪部分从未被用到"。这让知识点的质量评估、激活路径的有效性判断都有了更细的事实基础。

**缺口暴露更早、更准**。"知识单元命中但挖不出证据"是一类新的、有价值的信号：主题相关，内容缺失。它比"没有召回"更精确地指出了材料缺什么，可形成 Learning Event 供 Study 处理。

## 6. 证据挖掘不做什么

```text
不改写、不概括、不翻译原文——那会破坏可校验性；
不做推理和组合——组合多个片段得出结论是 Working Model 的职责；
不判断证据角色——直接证据还是支持性证据由 Rerank 决定；
不替代语义压缩——知识点是导入期形成的压缩摘要，服务检索；
  证据挖掘是使用期的按需定位，服务回答。二者方向相反，互不替代；
不扩大召回——挖掘不出证据时应如实暴露缺口，
  而不是放宽标准把背景内容当证据。
```

## 7. 总结

证据挖掘是检索与回答之间缺失的一层认知加工：检索找到主题，挖掘摘出证据。

它把"从混杂材料中分辨证据"从回答模型的隐式负担，变成一个独立、可校验、小模型可胜任的显式环节。

一句话总结：

```text
证据挖掘让系统引用的不再是"相关的主题"，而是"支撑答案的原文"。
```
