# 知识加工模式（Knowledge Processing Pattern）

同一个问题动作，在不同领域中需要完全不同的知识组织方式。

律师分析"是否有效"，脑中的结构是：事实 → 争议点 → 适用规则 → 证据 → 论证。DBA 分析"如何恢复"，脑中的结构是：当前状态 → 拓扑 → 配置 → 操作 → 验证。医生分析"是什么病"，脑中的结构是：症状 → 病史 → 检查 → 指南 → 诊断。

知识加工模式（KPP）把这种领域性的知识组织方式确立为正式对象：

```text
认知路由回答"这个问题走哪条路径、需要多深的处理"；
知识加工模式回答"这个领域的知识应该按什么结构组织和加工"；
推理模式回答"在组织好的结构上用什么方式推理"（见 reasoning-pattern.md）；
Working Model 是知识加工模式实例化后的认知工作空间（见 working-model.md）。
```

知识加工模式与推理模式是两个正交的轴：前者领域相关（法律、数据库、医疗、运维），后者领域无关（演绎、因果、比较、决策）。二者组合使用——数据库 KPP + 因果推理 = 根因分析，数据库 KPP + 决策推理 = 是否切换主库。拆成两轴的原因是避免模式库组合爆炸：N 个领域 × M 种推理只需要 N + M 个模式，而不是 N × M 个。

## 1. 为什么加工模式必须前置于检索

模式识别发生在问题理解阶段，在检索之前。根本原因是**词汇鸿沟**：

```text
用户问："如何重启集群"；
材料写的是："停止集群""启动集群""检查集群状态"；
材料中可能从头到尾没有出现"重启"这个词。
```

检索只能召回与问题字面或语义相近的内容。KPP 定义了证据槽位——停止方法、启动方法、验证方法——系统就可以带着槽位去检索：除了用原始问题召回，还按每个槽位的关键词补充召回。文档没有按用户问题的方式组织，不再是障碍。

这符合本系统的一贯立场：不要求材料按问题组织，由系统承担认知转换。

注意：加工模式与证据挖掘之间必须有完整的检索环节（槽位定向召回、Rerank）。证据挖掘只能加工已召回的内容，模式的槽位既指导"召回什么"，也指导"挖掘什么"。

## 2. 加工模式定义什么

一个知识加工模式至少定义：

```text
适用领域与问题形态：什么领域的什么问题应该激活这个模式；
知识加工槽位：回答这类问题需要哪几类知识，哪些必需、哪些可选；
槽位关系：槽位之间的先后、依赖或互斥（如恢复必须先于验证）；
加工规则：原文以什么形态进入槽位（逐字证据片段、结构化清单、状态标注）；
缺失行为：必需槽位缺失时先补召回还是直接暴露缺口。
```

典型的加工模式：

```text
运维操作类（restart / install / upgrade / migrate）：
  槽位 = 前置状态 / 操作步骤（按阶段）/ 验证方法 / 回退方法；
诊断类（recover / diagnose / troubleshoot）：
  槽位 = 现象 / 当前状态 / 可能原因 / 检查方法 / 处置 / 验证；
规则判定类（合规、资格、待遇）：
  槽位 = 事实 / 争议点 / 适用规则 / 例外条件 / 证据；
方案类（设计、选型）：
  槽位 = 目标 / 约束 / 候选方案 / 各方案事实 / 风险。
```

加工模式不定义推理步骤和输出契约——那属于推理模式（reasoning-pattern.md）。一个问题可以组合多个 KPP（主模式定槽位主体，辅助模式补槽位），但通常一个领域一个主模式。

## 3. 槽位填充即知识转换

材料的组织视角和问题的提问视角经常不同：

```text
材料写的是部署流程，用户问的是运维操作；
材料写的是命令清单，用户问的是操作步骤；
材料写的是配置参数，用户问的是如何调优。
```

知识转换**不是一个独立的处理层**。让模型自由地"把部署知识改写成运维知识"，产出无法校验，对能力有限的模型就是幻觉放大器。

转换以受约束的方式发生：KPP 的槽位就是目标视角的结构。证据挖掘按槽位从材料中摘选原文片段，片段填入槽位后，材料就已经按问题的视角被重组了——部署文档中的停止、启动、验证段落，填入运维操作模式的三个槽位，就是一份运维视角的回答结构。

关键性质：

```text
结构来自模式定义，不是模型即兴发明；
内容来自逐字摘选的证据片段，每一格都可回链到原文；
转换过程不产生任何无来源的新内容。
```

在槽位内容之上的进一步综合（如"停止步骤 + 启动步骤 → 重启流程"）发生在 Working Model 槽位层的受控综合步骤，同样要求出处绑定，见 `working-model.md` 第 4 节。

## 4. 槽位组装即关系发现

跨文档推理需要知识间的关系，但导入期全量抽取关系成本高、精度低。与 ActivationLink 的立场一致：认知结构应来自使用。

当来自三份不同文档的知识点分别填入同一模式的槽位时，系统实际上已经发现：它们同属一个操作（属于关系）、有执行顺序（先后关系）、验证依赖启动完成（依赖关系）。这些关系可形成 Learning Event，由 Study 观察跨多次使用的稳定复现后沉淀为知识点间的长期关系（见 study.md 第 6 节）。单次组装不建立关系。

## 5. 模式如何选择

KPP 是领域模板，选择应复用系统已有的领域机制，而不是新增一次自由分类：

```text
KPP 挂载在 Domain / Concept 上（预制数据的自然延伸）；
问题理解阶段的 Domain 匹配结果，同时决定候选 KPP；
同 Domain 下多个 KPP 时，按问题形态做一次轻量分类；
无 Domain 匹配或无挂载 KPP → 回退通用默认模式：
  默认模式的槽位就是原 Working Model 的固定结构
  （核心变量 / 已知知识 / 证据 / 缺口），保证回退路径永远存在。
```

强行套用不匹配的模式比不用模式更糟；回退是正常路径，反复回退的领域正是候选新模式的来源。

## 6. 模式库如何演化

```text
先验起步：常见领域手工设计少量模式，随 preset 数据一起维护；
使用中生长：某领域问题反复出现且现有模式覆盖不佳（反复回退、
  槽位反复空缺、用户反复纠正），Study 从多次 Learning Event 中
  提炼候选模式，经验证后加入模式库；
谨慎原则与其他长期记忆一致：候选不直接生效，跨多次事件验证。
```

### 与实践路径的边界

实践路径（study.md 第 7 节）是"KPP × 推理模式"的组合在具体任务上反复成功后的特化：它携带具体的变量组合、知识点范围和已知失效条件。KPP 提供领域骨架，实践路径记住这个骨架在某类任务中如何被成功填充和推理过。实践路径失效时，回退到通用的 KPP + 推理模式重新组织。

## 7. 加工模式不做什么

```text
不替代认知路由：路由决定走哪条路径，KPP 决定深想中的知识组织结构；
不定义推理：推理步骤、输出契约、冲突处理属于推理模式；
不替代 Rerank：证据与问题的相关性判断仍由 Rerank 承担；
不生成内容：槽位里只有摘选的证据片段与受控派生（带出处）；
不在导入期运行：KPP 作用于问题处理，不作用于材料导入。
```

## 8. 总结

知识加工模式让系统在检索之前先确定"这个领域的知识长什么结构"，用槽位驱动召回跨越词汇鸿沟，用槽位填充承载可校验的知识转换，用槽位组装在使用中发现知识关系。

一句话总结：

```text
知识加工模式回答"知识怎么组织"，推理模式回答"组织好之后怎么想"；
前者随领域生长，后者稳定通用，二者组合而不相互替代。
```
