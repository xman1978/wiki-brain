# 初始激活结构

知识单元只是局部记忆。

系统需要让这些局部记忆能够被激活和使用。

但这不意味着导入文件时就应该生成完整知识体系。

更准确地说：

```text
导入阶段形成知识单元和知识点；
使用阶段通过反复激活和反馈逐渐稳定 ActivationLink，并可能观察到候选领域和概念；
关系主要承担证据、溯源、索引和使用记录。
```

导入和预编译阶段可以计算 `KnowledgePoint -> Domain / Concept` 的静态匹配候选，但该结果不等于激活路径。`ActivationLink` 描述真实问题场景下的激活条件，只能在使用过程中根据独立召回、实际采用和反馈逐步创建并积累证据；precompile 不创建 ActivationLink，不论置信度高低——置信度从来只由真实使用产生的证据喂出来，预编译阶段没有这样的证据。

## 1. 为什么不是导入时生成完整知识体系

同一批材料可以服务不同使用者和不同问题场景。

例如同一份招标文件：

```text
采购管理人员会激活招标流程、资格审查、评标办法；
软件架构师会激活办公自动化系统、公文流转、统一用户、信创部署；
售前人员会激活客户需求、评分策略、投标响应、商务条款。
```

材料相同，但使用方式不同，形成的认知结构不同。

因此，知识体系不是材料天然自带的唯一结构，而是材料在使用中被反复激活后形成的认知结构。

## 2. 导入阶段形成什么

导入阶段应该形成相对稳定、可追溯的材料侧知识：

```text
材料来源；
知识单元；
知识点；
来源位置。
```

知识单元是围绕稳定主题或判断形成的最小完整知识包。

知识点是从知识单元中提取的可激活摘要。

来源位置让知识单元和知识点能够回到证据。

这些对象来自材料本身，因此可以在导入阶段形成。

## 3. 使用阶段形成什么

使用阶段形成使用者侧的认知结构：

```text
领域；
概念；
激活权重；
常用检索路径；
实践路径；
候选概念的合并和稳定。
```

领域和概念不应该仅因为某篇文档出现了某个词就变成稳定结构。

它们应该来自：

```text
预制的专业框架；
用户或系统反复使用；
多次 Learning Event 中被激活；
被实际回答采用；
得到反馈强化；
长期稳定存在。
```

## ActivationLink 激活链接

ActivationLink 是知识大脑在使用过程中逐渐形成的认知连接。

它连接的是某一问题主题、认知主题或使用场景，与一组相关知识点。通过知识点可以反查知识单元，再通过知识单元回到规范化 Markdown、预览 HTML 和原始来源。ActivationLink 因此不是孤立的标签挂载，而是能够一路追溯到证据的激活路径。

ActivationLink 不是普通全文索引，也不是一次检索日志。它是长期记忆中持续被证据校准置信度的激活路径——信任不是一次性贴上的标签，而是随每次使用不断被证据支撑或动摇的连续分数（机制见 `activation-convergence.md`）。系统面对问题时，应沿置信度已经收窄、足够可信的路径激活知识，而不是每次都把 ActivationLink 当成临时搜索结果。

ActivationLink 不会因为第一次被命中就立刻被信任，但也不会因为暂时不明朗就被移出候选池。单次命中、单次采用或单次正反馈，只是这条链接下某一条具体使用条件积累的第一个观测——足以让它的置信度小幅松动，不足以让它立即被直接服务。可信的使用条件应来自多次 Learning Event 中反复的激活、实际使用、正反馈和持续有效，让这条使用条件自己的置信度分布逐渐收窄；分布还宽、还没收敛时，它不会被弃置不用，而是继续以一个小比例的试探名额换取被观察的机会，直到证据把分数带到该去的地方。只有证据持续支撑、分布足够收窄的使用条件，才值得作为长期认知结构的一部分。

「实际使用」不等于「作为直接证据（direct）被引用」。同一知识点在不同问题里可能担任 direct 或 supporting 两种角色——被答案直接依据，或只是佐证、旁证。两者都是知识点被真实用上的信号，都不应被当作「未激活」。但两者对置信度的贡献不同：一条链接如果只是反复被拿来佐证、从未真正成为过任何答案的直接依据，这部分证据能维持它的置信度不滑落，却不足以单独把置信度推高到可以独立信赖的区间；只有反复作为 direct 依据，才应持续推高这条使用条件的置信度。supporting 角色的价值在于维持一条已经建立起来的路径不被误判为失效，而不是单独把一条路径的置信度撑上去。

ActivationLink 还应表达使用条件，而不只是表示某个概念下挂载了某个知识点。更准确地说，它表示：在某个认知视角下，当问题处于某类场景、目标、推理形式和注意焦点时，可以通过某个概念激活某个知识点和知识单元。例如，同一个「股票投资」概念下，成长投资场景更关注收入增长和行业空间，价值投资场景更关注估值和现金流，趋势交易场景更关注价格趋势和成交量。如果这些使用条件没有被沉淀，检索阶段只能根据文本相似度临时猜测，相似但不适用的知识容易被激活，历史反馈也难以精确作用到具体路径。

因此，ActivationLink 的目标形态是「认知入口规则」，而不是「问题文本到知识点的检索缓存」。一条成熟的链接应包含三个部分：

```text
触发条件：场景、目标、对象、约束、风险等级——什么样的任务会用到它；
认知条件：认知视角、领域 / 概念、推理形式、注意焦点——在什么认知框架下用它；
激活结果：激活哪些知识点或 Claim，以及它们在 Working Model 中建议承担的角色
          ——例如前提、判据、约束、风险、反例、行动步骤。
```

条件应表达为「实际观测到的条件组合」，而不是各维度独立取值的并集：不同任务下观测到的条件不能交叉拼接成从未出现过的组合，否则链接会随使用多样化滑向过度匹配。

链接的身份因此是「知识点 + 认知视角 + 使用条件」，不是知识点本身：同一个知识点可以在不同视角、不同任务条件下有多条链接，各自独立积累证据、维护自己的置信度分布。早期实现可以从单一视角、每个知识点一条链接起步，但这属于阶段性实现约束，不是设计承诺。

建议槽位角色与视角字段可以有三种来源：人工声明、编译时推断、使用中学习。前两种只是低置信起点，必须携带来源标记与置信度；只有真实使用信号（被采用、被纠正、反复有效）才能将其固化为可信条件。这与本文档的基本原则一致：认知结构来自使用，声明和推断只是给使用验证提供起点。

ActivationLink 的价值在于：

```text
让系统面对相似主题时快速激活相关知识；
减少对全文检索的依赖；
帮助系统形成领域和概念下的常用认知路径；
为 Working Model 提供激活起点和候选槽位角色；
暴露当前认知结构中的缺口；
支持后续 Wiki 页面编译。
```

当某条激活路径反复有效，它会成为领域和概念下的常用认知路径；当问题反复激活失败或只能依赖补充查找才能回答，它也会暴露当前认知结构中的缺口。这些稳定路径和缺口，都是后续 Wiki 编译的重要输入。

ActivationLink 是知识单元、知识点和长期认知结构之间的桥梁。

## Domain / Concept 与认知视角

领域和概念是通用定义，不承载视角差异化的使用方式：

```text
名称、描述、适用边界等描述稳定的认知入口和分类框架；
回答「这个知识点可能属于哪个认知分类」；
不表达「在某个视角、场景、目标下如何激活某条知识点」。
```

认知视角的差异只体现在 ActivationLink 上：

```text
同一领域和概念下，不同认知视角可以有不同的激活路径；
场景、目标、推理形式、注意焦点等使用条件属于 ActivationLink；
同一知识单元在不同视角下可以有不同的 ActivationLink，或仅有部分视角建立了激活路径。
```

因此，预编译阶段计算的 `KnowledgePoint -> Domain / Concept` 静态匹配候选，只缩小「可能相关的认知入口」，不预先生成视角差异化的激活路径。

## 4. 认知视角

同一批知识可以在不同认知视角下形成不同的激活路径和实践沉淀。

这个视角可以理解为：

```text
使用者；
角色；
任务类型；
专业方向；
长期使用环境。
```

例如：

```text
采购管理；
软件架构；
售前投标；
项目管理；
个人学习。
```

不同认知视角下可以有不同的 ActivationLink 和实践路径；领域和概念作为通用定义在各视角间共享。

因此：

```text
知识单元和知识点更偏材料侧和证据侧；
领域和概念更偏使用侧和认知侧。
```

## 5. 认知结构的价值

领域和概念不是为了把知识放进固定分类。

它们的价值，是让系统在面对问题时更会使用知识。

认知结构是知识利用质量的提升层。

它不追求替代补充查找，也不追求一次性整理出完整知识体系。

它通过一次次问题处理，持续提高系统理解问题、筛选材料和组织答案的能力。

认知结构至少提供四种能力：

```text
理解问题；
筛选材料；
组织答案；
发现缺口。
```

当用户提出问题时，系统会先用当前认知视角下已有的领域和概念理解问题。

这种理解会影响系统后续如何查找材料、如何判断结果重要性、如何组织回答。

补充查找可以帮助系统不要漏掉材料。

认知结构则帮助系统判断这些材料应该如何被使用。

因此，领域和概念不是和补充查找竞争的另一套检索结果。

它们是知识使用的框架：

```text
让问题被放到合适的领域中理解；
让相关材料围绕核心概念聚合；
让答案按稳定的判断维度展开；
让补充查找暴露出的缺口可以沉淀为候选概念和候选领域。
```

如果只有补充查找，系统可能找到相关内容，但很难判断哪些是核心、哪些是背景、哪些代表当前认知结构不足。

如果只有认知结构，系统又容易受限于已有领域和概念，漏掉尚未沉淀的新知识。

所以，二者必须互相补充。

从长期看，认知结构的成熟不是表现为材料数量增加，而是表现为知识使用质量提升：

```text
更快理解问题；
更少被相似但无关的材料干扰；
更稳定地找到核心知识；
更清楚地组织答案；
更准确地发现自己缺什么。
```

## 6. 领域

领域是经过预制或反复激活后稳定下来的知识使用范围。

它用于组织记忆、限定问题范围和引导检索。

领域不应该从每篇文档自由生成。

导入阶段最多只能形成候选领域。

稳定领域应来自：

```text
人工预制；
专业框架；
多次使用；
反馈强化；
候选领域合并。
```

## 7. 概念

概念是经过预制或反复激活后稳定下来的知识激活锚点。

它用于连接多个知识单元、知识点和问题场景。

概念不是文档中出现的所有名词。

导入阶段最多只能形成候选概念，或者尝试匹配已有概念。

稳定概念应来自：

```text
专业术语；
核心对象；
系统模块；
关键角色；
流程名称；
指标和公式变量；
反复被问题激活的知识锚点。
```

概念在使用中的新增、合并与拆分机制——演化信号、候选形成、人工确认与迁移语义——见 `concept-evolution.md`。

## 8. 关系

这里的关系不是开放知识图谱关系。

它不负责声明复杂语义关系，例如“支持”“反驳”“导致”“依赖”。

第一阶段的关系主要承担：

```text
证据；
溯源；
索引；
激活记录；
使用记录。
```

也就是说，它记录：

```text
知识点来自哪个知识单元；
知识单元来自哪个材料；
某个问题激活了哪些知识；
某次回答实际使用了哪些知识；
某个候选概念是从哪些使用记录中观察到的。
```

这些关系记录知识从哪里来、什么时候被激活、是否被使用，而不是试图构建完整知识图谱。

## 9. 总结

初始激活结构的目标，不是导入时整理完全部知识体系。

它的目标是让知识单元和知识点可以被使用，并为后续使用中的学习留下线索。

一句话总结：

```text
知识单元来自材料，认知结构来自使用；同一材料可以在不同认知视角下长出不同的 ActivationLink 和实践沉淀，而领域和概念作为通用定义共享。
```
