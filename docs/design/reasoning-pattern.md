# 推理模式（Reasoning Pattern）

推理模式是领域无关的推理形式库。

知识加工模式（knowledge-processing-pattern.md）把领域知识组织成 Working Model 的槽位结构之后，推理模式决定在这个结构上**用什么方式得出结论**：

```text
知识加工模式回答"知识怎么组织"（领域相关）；
推理模式回答"组织好之后怎么想"（领域无关）；
二者正交组合：数据库 KPP + 因果推理 = 根因分析，
              数据库 KPP + 决策推理 = 是否切换主库，
              规则判定 KPP + 演绎推理 = 合同是否有效。
```

## 1. 推理模式是什么

一个固定的、小规模的推理形式集合：

```text
deductive    演绎：规则 + 事实 → 结论（合规判定、资格判断）
inductive    归纳：多个案例 → 共同结论（经验总结、风险归纳）
causal       因果：现象 → 原因链 → 根因（故障诊断、原因解释）
comparative  比较：维度 × 对象事实 → 差异与取舍（选型、方案对比）
decision     决策：规则 + 条件 + 事实 → 是否应该（继续投入、切换）
procedural   编排：步骤 + 先后依赖 → 操作序列（重启、升级、迁移）
```

一个问题以主推理模式决定输出契约，可组合辅助模式（"为什么超支，还该不该继续投入"= decision 为主 + causal 为辅）。冲突不是推理模式，是所有模式都可能进入的控制状态（见 cognitive-routing.md 第 6 节）。

## 2. 工程形态：推理脚手架，不是推理引擎

这是本文档最重要的约束。推理模式**不是**符号推理机或通用演绎系统——那对目标模型（14B–30B）既不可行也不必要。每个推理模式的实现形态是：

```text
推理步骤模板：该形式下推理按什么顺序展开，每步依据哪些槽位；
输出契约：    答案应包含什么结构（结论 + 依据链 / 对比表 /
              步骤清单 / 条件化结论）；
程序检查：    结论必须回链到槽位中的证据（引用白名单校验）；
              必需槽位未满足时输出保守结论与缺口，不得强行补全；
              步骤依赖违反槽位关系时拒绝输出（如验证先于启动）。
```

也就是说：推理模式 = 受约束的生成模板 + 可程序化的输出检查。模型的自由度被限制在"按给定步骤组织已给定的证据"，每一步可验证。

## 3. 推理模式的输入是 Working Model

推理模式不接触原始材料、不触发检索：

```text
输入：已完成填充的 Working Model
      （槽位内容 + 槽位状态 + 派生知识，见 working-model.md）；
输出：Candidate Answer（写回 Working Model 第五层）+
      推理路径（每步依据的槽位与证据）。
```

槽位状态直接约束推理行为：

```text
必需槽位 confirmed        → 正常执行推理步骤；
存在 insufficient 槽位    → 相关推理步骤降级为保守表述并声明缺口；
存在 conflict 槽位        → 按思维模式规则升级冲突检测，
                            或输出条件化的分支结论；
派生知识参与推理时         → 其出处链一并进入推理路径。
```

## 4. 推理模式如何选择

选择应复用 Session 已提取的信号，不新增自由分类：

```text
intent（Session 四元组）→ 推理模式的主要映射来源：
  "如何操作/重启/部署" → procedural
  "为什么/什么原因"    → causal
  "哪个更好/如何选择"  → comparative
  "能否/是否应该"      → decision / deductive
  "有什么共性/经验"    → inductive
映射置信度低或 intent 缺失 → 回退默认形式：
  按证据状态直接组织回答（即证据直答的深路径形态），不套推理结构。
```

映射表是可配置规则起步，误配由回答质量信号（Learning Event）暴露，Study 修正映射，而不是每次让模型自由决定。

## 5. 推理模式不做什么

```text
不组织知识：槽位定义与填充属于知识加工模式与证据挖掘；
不做检索：缺证据时报告缺口，由检索环节补召回；
不产生新事实：只组合与推导已有证据，结论必须可回链；
不追求形式完备：六种形式覆盖常见问题即可，
  未覆盖的问题走回退路径，而不是扩充成推理形式的分类学；
不在低预算路径运行：证据直答（短路径）不需要推理模式。
```

## 6. 总结

推理模式把"自由推理"收敛为"在已组织好的认知工作空间上，按固定形式、可校验地组织结论"。它是四层调度的最后一环：

```text
思维模式（多深）→ 知识加工模式（什么结构）
  → Working Model（装进结构）→ 推理模式（怎么想）→ 回答
```

一句话总结：

```text
推理模式是领域无关的推理脚手架：步骤给定、证据给定、输出可查，
模型只负责把已经准备好的认知材料按正确的形式走完。
```
