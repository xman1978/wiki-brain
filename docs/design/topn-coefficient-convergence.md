# 证据筛选阶段 top-N / 目录检索系数自收敛设计

## 0. 背景

证据筛选阶段（`recallFromSources` → `rerankAndBuildEvidenceSet`，`internal/retrieval/service.go`）目前用固定值截断候选：Step 4 目录结构检索（outline recall）产出的候选，混入 RRF 排序时用一个固定系数加权；Step 6 RRF merge 之后，只有 `mergedRank < N`（N 固定为 10）的候选会进入 Step 7 rerank 判定。这两个值都是历史上拍定的常量，从未根据实际命中效果调整过。

目标：在不牺牲证据充分性的前提下，让 N 尽量小（降低 Step 7 LLM 判定的耗时/成本），同时让目录检索系数把真正需要的证据尽量排到 N 以内。这需要一个持续运行、自我修正的统计机制，而不是一次性调参。

## 1. 设计目标与约束

| 项 | 内容 |
|---|---|
| 核心目标 | 保证正确证据命中率的前提下，尽量缩小 top-N；调整目录检索系数，让正确证据尽量进入 top-N |
| N 初始值 | 当前生产值（10） |
| N 下限 | 5 |
| 系数初始值 | 当前生产值 |
| 系数下限 | 1 |
| 硬约束 | 调整过程本身不能造成大批证据筛选忽然失败——这条和"缩小 N"同等重要，不能用命中率换速度 |
| "完整性"的定义 | 由证据充分性判断（`VerifyEvidenceSufficient`，`fast_verify.md`）的结果定义，不构造脱离该判断之外的抽象完备性概念 |
| 具体数值 | 目标命中率、样本量门槛、步长等均不预先指定，先跑数据观察真实分布再定 |
| 适用范围 | 只影响慢/全量路径（`retrieveSlowPath` 及其 `recallFromSources`/`rerankAndBuildEvidenceSet`）；Fast path（ActivationLink 命中）与 Wiki 直答路径不经过这套候选截断，不受影响 |

## 2. 统计对象：R* 与它的保守代理

真正要校准的量不是"某条具体证据的排名"，而是每条 trace **首次达到充分性判断通过所需要的最小候选数**：

```
R* = min{ k : VerifyEvidenceSufficient(top-k 候选) = true }
```

逐一测试 k=1,2,3… 代价太高，工程上用一个可直接从现有数据得到的代理值：**该 trace 判定充分后，被实际引用的证据里排名最差的 `mergedRank`**（该字段已存在，`Evidence.MergedRank`/`candidate.mergedRank`，`internal/retrieval/types.go`）。

这个代理值和 R* 的关系是：`worst_cited_rank ≥ R*`，即它是 R* 的**保守上界**，不是无偏估计——LLM 的引用行为不保证严格遵守最小充分证据集，可能多引用了排名靠后的补充证据。这个偏差方向恰好是安全的（宁可高估所需 N，不会低估），与"不能因为调整导致大批失败"的硬约束方向一致，因此采用这个代理值，但设计文档和后续实现都必须明确标注它是**保守代理**，不能对外表述成"R* 的精确观测"或者说这套机制"有覆盖 R* 的有限样本保证"——有限样本保证覆盖的是这个代理值本身的分布，不是 R* 的分布。

## 3. 数据来源：复用现有充分性判断的重试链路，不额外采样

`VerifyEvidenceSufficient`（`internal/retrieval/service.go:623`）是慢路径下游一次独立的整体充分性判断，已经有一层重试：`widenEvidenceToFullUnits`——判不充分时把候选内容换成所属 KU 全文再判一次，解决的是证据挖掘漏内容的问题，跟候选排名无关。

在这层重试之后新增第二个重试轴：**内容扩展仍判不充分时，把候选池从 N 扩到 2N，重跑 Step 7 rerank 分类，再验证一次**。这个新重试只在"已经判定不充分"的 trace 上触发，对大多数一次通过的查询零额外成本，不需要为了拿校准数据专门牺牲一部分流量做"影子扩窗判定"。

### 结果分类（五类）

一条 trace 在这条重试链路上的最终结果，落入以下五类之一，各自对 N/c 校准的贡献不同：

| 结果 | 对 R* 的信息 | 是否进入 N/c 校准 |
|---|---|---|
| 首次即充分 | `R* ≤ N`（代理值 = worst cited rank，< N） | 是——精确上界样本 |
| 内容扩展后转为充分 | 无法判断是候选不足还是内容代表不足 | 否——单独计入 `content_rescue_rate` 诊断指标 |
| 候选池扩到 2N 后转为充分 | `N < R* ≤ 2N`（**区间删失**样本） | 是——核心校准数据，见第 4 节 |
| 候选池扩到 2N 仍不充分，且 RRF 候选总数 ≥ 2N | 真实的知识缺口/召回问题，与 N 无关 | 否——路由现有 `GapReasonJudgeFiltered` 等知识缺口机制 |
| RRF 候选总数 < 2N（池子在扩到 2N 前就耗尽） | **右删失**——既不能证明是 N 不够，也不能证明是知识缺口，因为 (实际候选数, 2N] 这段根本没被观察到 | 否，但单独打标统计，不得并入知识缺口计数 |

只有当 Step 6 RRF merge 实际产出的候选总数**大于当前 N** 时，"扩池到 2N"才有意义——候选总数本来就不足 N 的情况，问题出在召回阶段（现有 `retrieveSlowPath` 的重新解析 subject/intent、放开 Source 语义过滤两级兜底已经在处理这类情况），与 N/系数无关，不触发这条新重试，也不计入本机制的校准。

### 区间删失样本的处理

第三类（`N < R* ≤ 2N`）是区间删失数据，不是精确观测。工程上不引入完整的删失数据估计器（如 Turnbull estimator），而是取一个同样偏保守方向的简化：**用区间上界（2N，或救回时观察到的具体排名，取更大者）代入后续的分位数计算**——与 R* 代理值本身"宁可偏高"的处理哲学一致，避免额外的统计复杂度。

## 4. N 的调整：split conformal 分位数 + ACI 做漂移适应

放弃逐个候选 N 做 Beta 后验网格枚举的思路，改用与目标直接同构的方法：

**基础估计**：把一批校准样本（第 3 节分类里进入校准的那些，取其保守代理值）排序，取有限样本修正后的分位数——第 `⌈(n+1)(1-α)⌉` 位次（split conformal 的标准做法）——作为满足目标命中率 `1-α` 的最小 N。样本不足以支撑这个位次时（`⌈(n+1)(1-α)⌉ > n`），等价于"数据不够，暂不调整"，不需要另设最小样本量阈值，这个条件是分位数公式本身推出的。

**抗漂移**：用 Adaptive Conformal Inference（ACI，Gibbs & Candès）代替静态目标——维护一个随时间自适应的目标失败率 `α_t`，每来一条有效校准观测（仅限进入校准的那几类，不含被排除的类别）就更新 `α_{t+1} = α_t + γ(α_target - err_t)`，下一轮候选 N 用最近窗口在 `1-α_t` 下的分位数重算。这条机制的正式理论结果是：长期来看，实际失败率的滑动平均收敛到目标值，不管数据分布怎么漂移。

**必须明确的边界**：ACI 给出的是长期/滑动平均意义上的收敛保证，**不是**"每一次调整都不会造成短期失败率突增"的保证。把 ACI 当作满足"不能大批失败"这条硬约束的充分条件，是对这个理论结果的过度引申。ACI 只负责回答"下一步该往哪个方向、走多远看起来合理"，是否真的执行、执行多大幅度，必须由一个独立的安全闸门决定：

- 每周期 N 的变化幅度有上限（尤其是收缩方向，允许比增大更保守）；
- 独立监控一个较短时间窗口内的实际失败率，一旦明显超出目标（不是等 ACI 自己的滑动窗口慢慢纠正），立即把 N 回退到上一个已验证安全的值；
- 增大 N（保命方向）不设滞回，一旦触发立即生效；收缩 N 需要连续多个周期的数据都支持才生效。

ACI（方向判断）与安全闸门（幅度上限 + 异常立即回退）是两个独立、都必须存在的机制，不能相互替代。

## 5. 系数 c（目录检索系数）的调整

**目标表述**：不是单纯 `argmin_c N(c)`，而是"在充分性失败率、知识缺口率均不恶化的约束下，最小化所需 N"——否则 c 可能学会把本来就容易被判定通过的证据排得更靠前，代价是伤害了其他维度的召回质量，这不是我们想要的调整方向。

**搜索方式**：候选打分的各分量（目录检索分、全文检索分等）需要分别记录（而不是只留最终合成分），供离线重放：把第 3 节里"进入校准"的那批已标注样本（含被 2N 重试重新分类过的候选，它们天然带有比原始 top-N 更宽的真实相关性标签）在不同 c 下重新排序，观察对应的候选 N 变化。默认用网格搜索，**不假设 `N(c)` 关于 c 单峰**——c 的微小变化会引起候选重排序中的名次互换，而充分性判定是离散阈值，`N(c)` 完全可能是阶梯状、非单峰的；只有在真实数据验证过近似单峰之后，才考虑更高效的搜索方式。

**已知且接受的偏差**：用于 c 重放的标注数据，本质上是"当前 c 之下被观察到的候选集合"——如果换一个差异很大的 c，可能会让一些从未被判定过相关性的候选浮现出来，而重放只能在"已经被标注过"的候选里比较，无法凭空评估这些未知候选。完整消除这个偏差需要对固定的候选宇宙做全量重标注，这等于重新引入了此前决定放弃的"影子采样"成本。当前方案的取舍是：**c 只做当前值附近的小步长扰动**，不做大范围跳跃搜索——小范围扰动受这种自我强化偏差的影响远小于大范围重搜索，这是一个明确接受的近似，不是被忽略的问题。如果后续观察到 c 长期收敛不动或效果存疑，可以再考虑加一个独立的、低频率的"固定候选宇宙"审计动作，专门校验 c 是否存在系统性盲区，与 N 的校准逻辑分开处理，不混在一起。

## 6. 待实测确定的数值

以下数值均先跑数据观察真实分布再定，不在设计阶段预设：

- 目标命中率 `α`（初步方向：97% 量级）
- ACI 步长 `γ`
- 校准所需的最小样本量（由分位数公式自动导出，非独立配置）
- N 单周期收缩/增大的步长上限，收缩所需的连续达标周期数
- c 的网格步长、单周期最大调整幅度
- 触发安全闸门回退的失败率突增阈值

## 7. 与现有机制的关系

- 不改变 Fast path（ActivationLink）、Wiki 直答路径的行为——两者都不经过 `recallFromSources` 的候选截断。
- 不改变现有 `widenEvidenceToFullUnits`（内容扩展重试）、`retrieveSlowPath` 的两级空结果兜底（重新解析 subject/intent、放开 Source 过滤）——新机制是在这些之后再加一层，触发条件互不重叠。
- 不改变现有知识缺口检测（`GapReasonJudgeFiltered`/`GapReasonNoCandidates`）的既有判据，只是新增了"候选池在 2N 前耗尽"这一右删失状态，避免和真正的知识缺口混淆统计。
