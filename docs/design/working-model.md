# 临时认知模型

临时认知模型（Working Model）是知识大脑处理单个问题时临时建立的认知工作空间（Cognitive Workspace）——类似人脑的工作记忆：律师分析案件时，脑中保持的不是法条原文，而是"事实 → 争议点 → 证据 → 法条 → 可能结论"这个组织好的中间状态。Working Model 保存的就是当前问题所有已加工信息的组织结构。

它不是长期记忆，也不是最终答案。

它的作用，是把本次问题相关的长期知识、外部证据、缺口、冲突和推理路径组织起来，让系统能够围绕当前问题思考。

临时认知模型不是所有问题都需要。它只在认知路由的**深想路径**中构建（见 `cognitive-routing.md`）：找和浅想路径都不需要它。

可以概括为：

```text
长期记忆回答"我知道什么"；
检索回答"这个问题激活了什么"；
临时认知模型回答"本次问题应该如何被组织和思考"；
Learning Event 记录"本次处理对长期记忆有何学习价值"。
```

## 1. 为什么需要临时认知模型

如果没有临时认知模型，系统很容易退化为：

```text
检索一些材料；
把材料放进上下文；
生成一个看似合理的回答。
```

这不是思考。

真正的问题处理，需要先组织出本次问题的认知结构：

```text
问题是什么；
关键变量是什么；
已有知识能解释什么；
缺少什么；
证据支持什么；
证据反对什么；
应该如何推理；
回答边界在哪里。
```

临时认知模型就是这个结构。

但对找和浅想能覆盖的问题，构建临时认知模型只会增加不必要成本。因此它由认知路由触发，而不是所有问题的默认路径。

## 2. 何时构建：由认知路由决定

Working Model 只在深想路径中构建。进入深想有两种方式（判据和信号定义见 `cognitive-routing.md`，本文档不重复）：

```text
直通：问题形态本身要求组织多方知识
  （比较、取舍、组合问题、显式的设计与综合）；
升级：浅想路径遇到程序信号
  （证据分散 / 证据冲突 / 浅想弃答）。
```

升级进入时，浅想已召回的证据全部带入，槽位先用它们填，缺的槽位再定向补召回。构建 Working Model 的代价是"多想"，不是"重找"。

### 处理上限

Working Model 的构建规模受固定处理上限约束（上限定义见 `cognitive-routing.md` 第 4 节）：槽位数上限、insufficient 槽位补召回轮数上限、KPN 扩展跳数上限。上限是配置常量，不是每次问题都要做的判断。

### 扩展停止规则

当以下任一条件满足时，应停止向 Working Model 补充知识和上下文：

```text
新增知识点不能改变问题理解、判断边界或结论强度；
证据不足时，应标记缺口，而不是继续扩展；
处理上限耗尽时，应输出保守结论和缺口。
```

停止扩展不等于回答失败。它说明当前证据和成本下，继续扩散不会提高回答可靠性，应明确回答边界和待补缺口。

## 3. 它来自哪里

临时认知模型来自三类信息。

### 用户问题

用户问题提供目标和约束。

系统需要理解用户是在问事实、方法、判断、解释、决策，还是要求设计。认知路由根据问题形态判断是否进入深想。

### 长期记忆

长期记忆提供已有知识。

系统会激活相关领域、概念、知识点、关系、经验和实践路径。

### KnowledgePoint Network 提供上下文

Working Model 不直接从 KPN 中搜索答案。

KPN 的作用，是在核心 KnowledgePoint 已经被召回之后，补充本次问题可能需要的上下文：

```text
相关变量；
前置概念；
边界条件；
反例；
补充知识；
对立知识；
可能缺失的知识点。
```

Working Model 可以请求 KPN 补充上下文，但 KPN 补充必须围绕当前 Working Model 的槽位、边界、反例和缺口。Working Model 不能把 KPN 当成无限知识扩展工具。

KPN 的激活条件、扩展边界和停止条件详见 `docs/design/kpn.md`。当处理上限或 KPN 停止条件满足时，应停止扩展并保留已获得的上下文。

### 外部证据

当长期记忆不足时，系统需要查找外部证据。

这些证据用于验证假设、补充事实、发现反例或确认边界。外部查证不是独立的处理模式，而是 insufficient 槽位的补证行为之一。

## 4. 它包含什么：三层结构

Working Model 没有固定字段。它的槽位结构由本次问题命中的知识加工模式（见 `knowledge-processing-pattern.md`）实例化生成：法律问题实例化出事实/争议点/规则/证据，数据库问题实例化出状态/配置/操作/验证。模式不匹配时回退通用默认模式，其槽位即传统的核心变量/已知知识/证据/缺口。

无论槽位如何变化，Working Model 统一抽象为三层：

### 第一层：Problem（问题）

整个工作空间的根：本次要回答什么、不回答什么。来自问题理解（含 Session 四元组），是质量检查中"问题边界清晰"的依据。

### 第二层：Slots（知识加工槽位）

由知识加工模式实例化生成的槽位集合、各槽位填入的内容，以及每个槽位的判定状态。

**填充规则**：进入槽位的应是经过证据挖掘（见 `evidence-mining.md`）的片段级证据，而不是完整的知识单元正文。每条片段可回链到来源位置；未经挖掘的整段材料只应在挖掘回退时例外进入，并保留退化标记。证据集合应同时包含支持证据和反对证据，系统应避免只收集支持自己初始判断的信息。

**槽位状态**：程序维护的显式标记，是本层最重要的机制：

```text
confirmed     已确认：有充分证据支撑；
pending       待确认：有证据但未验证或来源单一；
conflict      冲突：槽位内证据互相矛盾；
insufficient  证据不足：必需槽位未填满或片段挖掘为空。
```

槽位状态是充分性判断的直接依据：必需槽位全 confirmed 才可完整推理；insufficient 触发槽位定向补召回（受上限约束），补后仍空则显式输出缺口；conflict 不强行裁决，输出条件化的分支结论。空槽位不是失败，是精确的知识缺口信号，可形成 Learning Event。

**可选综合（派生知识）**：槽位内容之上可做受控综合——停止步骤 + 启动步骤 → 重启流程；多个案例 → 共同风险；多条日志 → 根因假设。综合有一条不可妥协的约束：**每条综合结果必须绑定它所依据的槽位证据（片段级出处），由程序做白名单校验；无出处的综合内容不得存在，更不得进入结论**。这与引用校验、证据挖掘的原文校验是同一设计思想。综合结果只存在于本次 Working Model 中；若反复出现且稳定有效，经 Learning Event 由 Study 沉淀（如成为 KPN 关系或实践路径素材），而不是直接写入长期记忆。

### 第三层：Conclusion（结论）

推理模式（见 `reasoning-pattern.md`）在前两层之上执行后产出的回答草稿，含：

```text
结论；
推理路径：每步依据的槽位与证据（含综合结果的出处链）；
回答边界：确定性、适用范围、条件与风险。
```

回答生成器直接读取本层，不重新组织证据。

## 5. 生命周期

Working Model 随问题创建、随回答销毁，中间经历明确的阶段，且在处理过程中被不断修正：

```text
Created            路由进入深想（直通或浅想升级）→
                   知识加工模式实例化槽位（不匹配时回退默认模式）
  -> Filling       激活长期记忆 → 槽位定向召回 → Rerank →
                   证据挖掘填充槽位，更新槽位状态；
                   浅想升级进入时，已召回证据先行填入
  -> Refining      insufficient 槽位定向补召回（受上限约束）；
                   槽位内容按需做受控综合（带出处校验）
  -> Reasoning     推理模式在槽位与综合结果上执行；
                   conflict 槽位输出条件化分支结论
  -> Concluded     结论写入第三层，质量检查
  -> Discarded     回答输出后销毁；仅学习价值经 Learning Event 流出
```

如果新证据推翻了原有判断，临时认知模型应该被更新。

如果发现关键槽位缺失，系统应该补充。

如果冲突无法解决，回答中应该保留不确定性。

## 6. 质量检查

临时认知模型组织完成后、输出回答前，系统应对其做质量检查：

**1. 问题边界清晰**：明确本次问题要回答什么、不回答什么。不能把相邻问题、背景信息或用户未询问的判断混入当前模型。

**2. 槽位覆盖充分**：必需槽位有证据填充，每个关键判断都有对应证据。不能把推断、类比或未验证假设当作已确认事实。

**3. 知识缺口显式**：不能把未知内容伪装成已知。缺口应被明确标记，并决定是补召回、外部补证还是保守回答。

**4. 支持与反对证据并存**：不能只收集支持当前结论的材料。Working Model 应主动保留反例、边界条件和反对证据。

**5. 推理路径可检查**：结论应能回溯到槽位、证据和知识单元。若无法说明某个结论来自哪些证据和推理步骤，该结论不应进入最终回答。

**6. 回答边界匹配证据强度**：证据弱时只能给出保守结论。不能把低置信度推断表达为确定判断，也不能忽略时效性、冲突和适用边界。

**7. 不直接沉淀为长期知识**：Working Model 是一次性思考结构，随本次问题结束而消散。它不能直接写入长期记忆、不能直接晋升为 ActivationLink 或 Wiki 页面。只有 Working Model 暴露的学习价值经 Learning Event 记录、Study 处理后，才可能影响长期记忆。

质量检查未通过的模型，应回到补充检索或模型修正，而不是强行生成看似完整的回答。

## 7. 与其他模块的关系

### 与知识检索的关系

知识检索为临时认知模型提供被激活的长期记忆和外部证据。

但检索结果不是临时认知模型本身。

检索结果必须先经问题级 Rerank 逐条分类，再经证据挖掘摘选为片段级证据，按知识加工模式的槽位聚合并完成覆盖检查和冲突检查，才能进入临时认知模型。

Rerank 是逐条证据分类器，不是 Top-K 选择器：它只判断每条候选证据是否与问题匹配，以及它是直接证据、支持性证据还是无关证据，并将所有直接证据和支持性证据交给后续环节；它不理解完整回答结构，也不决定是否需要原因或推理步骤。临时认知模型接收的不是原始召回片段，也不是 Rerank 的分类结果本身，而是聚合与检查之后已经绑定证据的事实、规则、实体关系、变量和缺口。它在此基础上构建候选推理路径，并明确区分：

```text
文档明确规定的事实和规则；
可以从事实和规则推导出的判断；
缺少证据或量化标准的部分；
因冲突或覆盖不足而无法确定的结论。
```

### 与 Learning Event 的关系

Working Model 不默认生成完整过程 Trace。

Working Model 内部如何组织槽位、修正推理、逐步推导，不属于 Learning Event 的记录范围。

若 Working Model 暴露了激活失败、知识缺口、路径冲突或用户纠正等学习信号，可形成 Learning Event。Learning Event 记录的是学习事实，不是 Working Model 的完整内容。

### 与学习的关系

Study 的输入是 Learning Event，不是 Working Model 本身。

如果某类知识组织路径在多次 Learning Event 中反复被证明有效，Study 可沉淀为实践路径。如果某类 Working Model 反复暴露同类失败信号，Study 应调整 ActivationLink、Concept 或知识状态，而不是保存 Working Model 的完整结构。

更完整的链路如下：

```text
复杂问题进入深想路径
  -> Working Model 组织本次槽位、证据和推理路径
  -> 若暴露学习价值，形成 Learning Event（如 activation_success、repeated_success）
  -> Study 从多次事件中观察结构相似性（任务类型、核心变量组合、步骤框架）
  -> 提炼候选实践路径
  -> 经独立验证后，成为深想内可复用的快路径模板：
     命中时跳过从零组织，直接按已验证的方式实例化和填充
```

Working Model 只贡献学习信号，不直接晋升为实践路径。单次成功或单次变量组合不足以沉淀模板；需要多次稳定事件，且核心变量组合跨事件高度相似。候选实践路径的验证、晋升边界和与 ActivationLink 的区别见 `study.md` 第 7 节。

## 8. 总结

临时认知模型是知识大脑的工作记忆。

它让系统不是简单调用知识，而是围绕当前问题组织知识。

Working Model 是深想路径的一次性思考结构，不需要默认完整保存。Working Model 内部推理过程不进入 Trace。

只有当 Working Model 的结果暴露了长期学习价值时，才产生 Learning Event，例如：

```text
某个知识缺口被确认；
某个 ActivationLink 被证明无效；
某组知识出现冲突；
用户纠正了 Working Model 的判断；
某类问题反复需要相同的知识组织路径。
```

Working Model 本身不是长期记忆，其完整内容不应直接沉淀。Study 只从 Learning Event 中抽取长期记忆调整信号，不从 Working Model 的完整推理过程学习。

一句话总结：

```text
临时认知模型把长期知识和外部证据组织成本次问题可推理、可检查、可追踪的工作结构：
问题定边界，槽位装证据并如实报告状态，结论只从有出处的内容里长出来。
```
