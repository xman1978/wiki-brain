# Wiki-Brain V2 实现概览（认知材料构建版）

## 定位

V1 完成后，系统已具备学习转化能力：检索事件驱动 ActivationLink 演化，学习结果改变检索行为，稳定主题沉淀为可读 Wiki。但这些成果对程序而言仍是"文本 + 检索字段"：稳定结论藏在 Markdown 里，链接只回答"激活哪个 KP"而不回答"拿它做什么用"。

V2 的目标是把 V1 的成果**编译为 V3 认知系统可直接消费的结构化认知材料**：

```text
v1 的使用记录、ActivationLink、Wiki、KP、证据
  → v2 认知材料编译
  → v3 按问题实例化 Working Model 并推理
```

**V2 不做在线推理，不追求"会思考"**：不实现认知路由、Working Model、推理执行、查证、冲突检测、实践路径、反思学习。这些全部属于 V3。

**V2 交付的是编译基础设施、材料 Schema 和种子材料，不是成品材料库。** 视角、槽位角色等使用侧字段在 V2 只能来自人工声明和编译时推断，是低置信起点；它们的成熟依赖 V3 上线后的使用信号回流（谁被采用、谁被纠正、反复是否有效）。这符合"认知结构来自使用"的设计原则（`precompile.md`）——声明和推断只是给使用验证提供起点。

设计依据：`design.md`（知识表达的分层）、`wiki-compilation.md`（页面与 Claim 同源、认知包）、`precompile.md`（ActivationLink 认知入口规则）、`knowledge-processing-pattern.md`、`reasoning-pattern.md`。

---

## 与 V1 / V3 的边界

| 能力 | V1 | V2 | V3 |
|------|----|----|----|
| 稳定知识表达 | Wiki Markdown 页面 | 页面 + Claim 同源双产物 | 消费 Claim 填充槽位 |
| ActivationLink | 每 KP 一条，检索缓存语义 | 多链接（KP + 视角 + 条件），认知入口规则 Schema | 在线匹配、槽位角色学习、全自动晋升 |
| KPP | 无 | 模式库定义 + 槽位 Schema（不执行） | 前置识别 + 槽位驱动检索 |
| RP | 无 | 输出契约定义（不执行） | 在 Working Model 上执行 |
| 认知视角 | 无（单一视角） | 视角对象 + 按视角组织材料 | 会话在线推断 + 视角化学习累积 |
| 学习闭环 | 检索事件 → Study | + Wiki / Claim 使用聚合 | + 槽位角色、模式误配等信号回流 |

## 核心交付

### 1. Claim 层（Wiki 编译双产物）

依据 `wiki-compilation.md`「编译产物：页面与 Claim 同源」。

```text
编译输出扩展：在页面 Markdown 之外产出 claims 数组，每条包含
  claim_id、结论文本、依据 point_ids、成立前提、待验证 / 冲突标记；
同源约束：claims 与页面共享同一份证据白名单，随 wiki_revisions 版本化，
  页面重编译时整体更新；claim_id 跨版本延续（按 point_ids 与结论
  相似度继承，无法继承时新建并记录替代关系）；
不重复建模：置信度与时效由 point 的 lifecycle、confident_count 与页面
  status 派生，冲突复用 KPN contradicts，不落新字段；
唯一入口：Claim 只能由编译产生，不提供独立编辑 API。
```

### 2. KPP 模式库（定义，不执行）

依据 `knowledge-processing-pattern.md`。

```text
手写小库起步：运维操作类 / 诊断类 / 规则判定类 / 方案类，
  挂载 Domain / Concept；
槽位 Schema：每个槽位声明——
  名称与角色（前提 / 判据 / 约束 / 风险 / 反例 / 行动步骤等）；
  必需性（必需 / 可选）；
  可接受输入类型（Claim / 片段级证据 / 变量值）；
  证据要求（必须可回链 KP / KU）；
  缺失与冲突时的处理策略（补召回 / 显式缺口 / 保守结论）；
无匹配回退：通用默认模式（核心变量 / 已知知识 / 证据 / 缺口）。
```

前置识别、槽位驱动召回扩展是 V3 的执行能力；V2 只保证模式与槽位是良定义的、可被回放验收消费的。

### 3. RP 输出契约（定义，不执行）

依据 `reasoning-pattern.md`。六种推理形式（演绎 / 归纳 / 因果 / 比较 / 决策 / 编排）以 prompt 模板文件 + 输出 JSON Schema 承载，不建表。契约定义：步骤模板、结论必须携带的槽位引用、必需槽位不满足时的保守结论触发条件。V2 定义契约供 KPP 槽位声明引用，执行留给 V3。

### 4. 认知视角与 ActivationLink 认知化

依据 `precompile.md`「认知入口规则」。

```text
perspectives 表：视角定义（名称、描述、来源：preset / 人工）；
链接身份迁移：取消 UNIQUE(point_id)，身份改为
  （point_id, perspective_id, 条件组）；存量链接迁移到默认视角，
  默认视角下的匹配行为与 V1 完全一致（回归保障）；
条件表达修正：从"各字段独立并集"改为"观测到的条件元组集合"，
  不同 trace 的条件不交叉拼接成从未观测过的组合；
认知化字段：启用 scene / goal，新增建议槽位角色；
来源与置信：每个使用侧字段携带来源标记
  （declared 人工声明 / compiled 编译推断 / learned 使用学习）与置信度；
  learned 只能由 V3 使用信号写入，V2 预留写入接口。
```

### 5. 认知材料访问契约（认知包 + 动态解析）

依据 `wiki-compilation.md`「认知包」。V3 消费材料的唯一入口是一份两部分的访问契约：

```text
静态组装（认知包）：按主题 / 概念 / 视角装配 Wiki 页面、Claim 集合、
  verified 链接、KPN 上下文关系、缺口与各组件版本指针；
  视图 + 版本引用，不落新存储；组件失效沿既有 lifecycle /
  needs_recompile 机制传导，包本身无独立同步逻辑；

动态解析（槽位证据解析）：slot → evidence resolver → KP / KU 片段查询，
  内部复用 V1 的检索与证据挖掘服务；覆盖没有已编译 Wiki / Claim 的
  长尾知识——片段级证据按设计是问题时在线摘选的（evidence-mining.md），
  不可预编译，长尾覆盖因此走契约的动态分支，不是回退旧检索路径。
```

两部分共用同一套回链与版本语义。V2 交付契约定义与静态组装实现，动态解析接口在 V2 定义签名并供回放验收调用；在线消费方是 V3。

### 6. Wiki 防固化要素补齐（材料相关部分）

主题页 / 概念页补齐：适用边界、争议点（contradicts 呈现）、依赖的 ActivationLink、被替代 / 修订记录、最近更新时间。方法页 / 经验页 / 问题页 / 决策页推迟到 V3——它们依赖实践路径与使用记录，V2 没有这些输入。

### 7. Study 扩展：表达层使用聚合

聚合 path_type=wiki 的 traces：页面直答命中率、sufficient=false 回落率、被引用 Claim 分布，进入学习报告；沿用 `wiki_update_candidate` 命名产生重编译候选。**不改激活类事件的统计口径**，页面命中不计入链接成功统计。

## 验收标准（硬）

核心判据：**给定种子领域的典型问题类型，系统无需从 Wiki 文本临场解析，就能提供已定义的槽位、候选 Claim、证据链、边界与冲突。**

```text
回放验收（零推理）：在金标题集（见下）上程序化检查——
  问题能命中一个 KPP 或显式回退默认模式；
  必需槽位的 Claim / 证据候选覆盖率达到模块文档阈值（两步制定标，见下）；
  空槽位被显式识别为缺口，而非报错或被无关内容填充；
Claim 链路：每条 Claim 可沿 point_id 回链 KU 与来源位置；
  重编译后 claim_id 延续与替代关系可验证；
链接迁移回归：默认视角下匹配结果与 V1 逐例一致；
  同一 KP 在两个视角下可建两条条件不同的链接并独立命中；
认知包：组件版本指针与实际 revision 一致；
  底层 KP 失效后包内对应组件可观察到失效传导；
范围守住：全程无新增在线 LLM 推理路径（编译类调用除外）。
```

**金标题集与两步制定标**：验收前从 V1 真实 traces 抽样并人工标注，固定金标题集，分层覆盖高风险、冲突、词汇鸿沟类问题。指标名固定：证据召回率、引用正确率、槽位完整率（V3 阶段追加路由准确率、冲突识别率、时效合规率、学习增益、错误强化率）。**阈值不预先拍定**：先在金标题集上测出基线，再定阈值写入各模块实现文档——没有基线的阈值是假精确。金标题集同时作为 V3 晋升机制的独立验证集，一份投入两用。

验收范围限定在种子领域（首批手写 KPP 覆盖的领域），不要求全库涌现——材料全面成熟是 V2 机制 + V3 使用共同的结果。

## 实现顺序

```text
1. Claim 层（编译双产物 + claim_id 延续）
2. 视角对象与 ActivationLink 迁移（身份、条件元组、认知化字段）
3. KPP 模式库 + 槽位 Schema（preset 起步）
4. RP 输出契约（prompt 模板 + Schema 文件）
5. 认知材料访问契约（静态组装实现 + 动态解析接口签名）
6. Wiki 防固化要素补齐（主题 / 概念页）
7. Study 表达层使用聚合
8. 回放验收 harness
```

每步 `go test ./...` 全绿后进入下一步，不并行推进。

## V2 成功标准

```text
材料可消费：  回放验收在种子领域全部通过，V3 可以只经材料访问契约
              （静态认知包 + 动态槽位证据解析）组织推理输入，
              长尾问题由动态解析覆盖，不解析页面文本；
同源不漂移：  页面与 Claim 任何时刻同版本，无独立编辑入口；
              Claim 全部可回链到 KU 与来源；
链接可分化：  同一 KP 在不同视角 / 条件下可有独立演化的多条链接，
              存量行为无回归；
低置信显式：  declared / compiled 字段全部带来源与置信标记，
              不冒充已验证结论；
存储不膨胀：  认知包无独立内容存储；Claim 不重复建模置信 / 冲突 / 时效；
边界守住：    无在线推理；Study 仍只调整长期记忆；
              激活类统计口径不受表达层聚合影响。
```

V2 完成后，V3 的边界即可收窄为：接收认知包，针对当前问题完成路由、实例化 Working Model、推理与回答，并将使用信号回流——见 `docs/impl/v3/readme.md`。
