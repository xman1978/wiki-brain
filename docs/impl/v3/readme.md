# Wiki-Brain V3 实现概览（认知系统版）

## 定位

V2 完成后，系统拥有可供程序直接消费的认知材料：Claim、KPP 槽位定义、RP 契约、认知化的 ActivationLink 和认知包。V3 的目标是在这些材料之上实现真正的认知执行——按问题性质选择思考方式，实例化 Working Model 完成受约束推理，并把使用信号回流给 V1 的学习闭环和 V2 的材料编译。

```text
问题理解
  → 认知路由（找 / 浅想 / 深想）
  → 深想：选择 KPP / RP，ActivationLink 激活材料
  → 填充 Working Model（Claim、片段级证据、变量）
  → KPN、证据挖掘与外部补证处理缺口
  → 推理与回答
  → 学习事件回流 v1（Study 调整长期记忆）/ v2（材料重编译与字段固化）
```

**V3 不重新定义知识存储**：不新增知识表达层对象，只消费 V1 / V2 的对象与 Schema。Working Model 是 per-question 的一次性思考结构，不落长期存储；它暴露的学习价值经 Learning Event 进入 Study，不直接写长期记忆。

V3 的验收底线继承 V2 的判据：深想路径的推理输入全部经 V2 的认知材料访问契约获取——静态认知包覆盖已编译知识，动态槽位证据解析覆盖长尾知识——而不是把复杂提示词包装成"认知系统"。

设计依据：`cognitive-routing.md`、`knowledge-processing-pattern.md`、`reasoning-pattern.md`、`evidence-mining.md`、`working-model.md`、`study.md`、`lifecycle.md`、`wiki-compilation.md`、`kpn.md`、`concept-evolution.md`、`design.md` 第 7-9 节。

## 与 V2 的边界

| 能力 | V2（材料） | V3（执行） |
|------|-----------|-----------|
| KPP | 模式库定义 + 槽位 Schema | 前置识别、槽位驱动检索扩展、按槽位定向证据挖掘 |
| RP | 输出契约定义 | 在 Working Model 上按契约执行 |
| Claim | 编译产出与版本管理 | 作为槽位候选被消费（程序校验回链） |
| ActivationLink | 多链接 Schema、declared / compiled 字段 | 在线匹配、learned 字段写入、全自动晋升 |
| 认知视角 | 视角对象、按视角组织材料 | 会话在线声明 / 推断、按视角累积学习 |
| Wiki | 主题 / 概念页 + 防固化要素 | 方法 / 经验 / 问题 / 决策页、自动重编译候选 |
| 学习 | 表达层使用聚合 | 槽位角色、模式误配、实践路径等新信号回流 |

## 核心能力

### 1. 认知路由

依据 `cognitive-routing.md`。问题按形态路由到三条路径：

```text
找：  定位检索，返回命中内容和来源；
浅想：证据直答，召回并经 Rerank 分类后的证据交给回答模型；
深想：按 KPP 组织 Working Model 槽位，按 RP 推导。
```

路由基于 intent 查表判定；升级链唯一且单向（找 → 浅想 → 深想），由程序信号触发：无字面命中、证据分散、证据冲突、浅想弃答。深想内部由固定上限常量约束：KPN 扩展最大跳数、insufficient 槽位补召回最大轮数、槽位数上限、单问题最大模型调用次数。任一上限耗尽即基于已有槽位输出保守结论和显式缺口。

硬约束由程序强制：高风险 Domain 不停留在找路径直答；conflicted 链接命中必须触发冲突检查；candidate 链接任何路径下不得直接决定答案。

### 2. 架构落地：认知能力 → Service，思维路径 → Agent

依据 `design.md` 第 1、9 节。把 MVP/V1 的模块化流水线重组为可编排的认知服务：

```text
Service（internal/service/ 或按现有模块演化）
  问题理解 / 认知结构激活 / 补充查找 / 结果融合 / 缺口识别 /
  证据回溯 / 临时认知建模 / 推理组织 / 学习事件记录 / 学习沉淀

Agent（internal/agent/）
  每条路径一个 agent，按该路径编排 service 调用序列；
  路径升级 = agent 间移交，携带已完成的中间结果，不重复检索

约束
  service 负责数据访问、索引、模型调用、错误处理、trace 输出；
  LLM 只在 service 内部需要语义判断的局部步骤被调用；
  认知能力不做成模型自由调用的 skill。
```

MVP/V1 的 Retrieval、Answer 等模块内部逻辑大量复用，重组的是调用编排层。

### 3. KPP 在线执行

依据 `knowledge-processing-pattern.md`，消费 V2 的模式库。

```text
前置识别：问题理解阶段复用 Domain 匹配选定模式，零新增 LLM 调用；
  无匹配回退通用默认模式；
槽位驱动检索扩展：按槽位关键词补充召回，跨越词汇鸿沟
  （问"重启"，材料只写"停止 / 启动"）；
定向证据挖掘：按槽位摘选片段级证据填入，每格可回链原文，无自由改写；
充分性判断：以必需槽位填充率替代"是否存在 direct 证据"，
  空槽位即显式知识缺口，先补召回，仍空则如实输出；
模式库演化：反复回退或反复出现的领域结构，经 Study 提炼候选新模式。
```

补召回与定向摘选统一经 V2 材料访问契约的动态解析接口执行，不绕过契约直连检索模块。

### 4. Working Model + RP 执行

依据 `working-model.md`（三层结构）与 `reasoning-pattern.md`。per-question 生命周期，不落长期存储：

```text
L1 问题层    本次问题与边界（含 Session 四元组、认知视角）
L2 槽位层    KPP 实例化槽位 + 填充内容（Claim / 片段级证据 / 变量），
             每槽位状态：confirmed / pending / conflict / insufficient
             （程序维护，驱动补召回、升级与缺口上报）
L3 结论层    RP 执行后的回答草稿 + 推理路径 + 回答边界
```

槽位填充规则：Claim 经程序校验 point_id 回链后填入，是候选之一而非唯一依据；受控综合（如 Stop+Start → Restart）必须绑定片段级出处，程序白名单校验，无出处不得进入回答。

RP 按 V2 契约执行：六种形式（演绎 / 归纳 / 因果 / 比较 / 决策 / 编排），Session intent 映射选择（可配置规则，误配经 Learning Event 由 Study 修正），主辅可组合；结论必须回链槽位证据，必需槽位不满足时输出保守结论。

质量检查（输出前，`design.md` 第 7 节）：问题边界、变量完整性、证据覆盖、缺口显式性、正反证据并存、推理可回溯性、回答边界与证据强度匹配。

### 5. 查证模式与外部证据

依据 `design.md` 第 3 节。库内知识不足、可能过期或风险较高时，由问题和槽位缺口驱动外部查找：列出待确认事实点 → 查找外部证据 → 比较来源可靠性与时效 → 区分已确认 / 未确认 / 争议。外部证据进入 EvidenceSet 时标记来源类型，与库内证据统一比较；发现库内知识可能过期时触发 Learning Event 提示人工核实来源（不直接改 lifecycle，见 `lifecycle.md`）；被反复采用的外部证据可提示导入为正式 Source。

**外部证据必选持久化**（不是可选项——来源可靠性比较、时效淘汰和复核都依赖落库）：

```text
每条记录固定字段：URL、快照 / 版本时间、发布者、来源等级、抓取时间、
  有效期、引用片段、适用范围；
来源等级与 sources 的 trust tier 同一套等级体系（见 V2 readme）；
高风险问题最低证据门槛：至少一条等级达标且未过期的外部证据，
  否则回答只输出边界与缺口，不给结论。
```

### 6. 冲突检测模式

冲突信息直接来自 KPN 的 contradicts 关系（检索时动态查出），不引入持久化的 conflicted 知识状态——冲突是知识之间的关系，不是知识自身的属性。识别冲突点，分别整理支持与反对证据，判断冲突来自事实、条件、时间还是立场差异；可消解的回到来源确认，不可消解的输出条件化结论与冲突边界。ActivationLink 自身的 conflicted 状态在 V3 启用：命中即触发冲突检查，不直接作为答案依据。

### 7. 实践路径与经验路径

依据 `study.md` 第 7 节。

```text
形成：同类问题在深想下 repeated_success，且多次事件的 scene / goal /
      核心变量组合高度相似 → Study 提炼候选实践路径；
内容：适用任务类型、核心变量组合与检查顺序、建议激活的领域 / 概念 /
      KP 范围、步骤框架、适用边界与已知失效条件；
验证：候选路径在新问题中按模板组织仍有效 → 晋升为稳定模板；
调用：路由识别到匹配任务类型时优先走经验路径；
      失效或超出边界时回退深想重新探索。
```

实践路径是"KPP × RP"组合在具体任务上反复成功后的特化；反复有效的实践路径是 Wiki 方法页的编译输入。

### 8. 反思学习

由明确失败信号触发（用户纠正、连续追问同一缺口、检索失败、推理路径失效）：回看问题理解、检索覆盖、模型组织、推理路径、长期记忆五个环节定位不足，输出学习建议与缺口记录，形成 Learning Event 供 Study 消费。单次反馈不重写稳定知识；同类问题反复失败才推动结构性修正。反思学习聚焦知识层信号，Agent 任务级复盘不属于知识大脑职责。

### 9. 认知视角在线化

消费 V2 的视角对象：会话可声明或推断当前视角；检索与学习按视角维度累积，一个视角的强化不污染其他视角；同一 KP 在不同视角下沿各自链接独立演化；Wiki 按视角编译，同一批 KU 在不同视角下可形成不同页面。

### 10. Wiki 编译完整版

在 V2 主题 / 概念页基础上补齐：方法页（实践路径输入）、经验页（反馈学习输入）、问题页（反复出现的问题类型）、决策页（高风险判断场景）；重编译全自动候选（repeated_success / repeated_failure / knowledge_conflict / user_correction / concept_boundary_signal / 知识状态变化驱动，每次附 Learning Reason）；认知预算约束引用：low 预算可直接引用 Claim，medium 检查适用边界，high 必须回到证据与 Working Model，不得只依赖 Claim 或页面。

### 11. Concept / Domain 演化完整版

依据 `concept-evolution.md` 与 `study.md` 第 3、8 节：concept_boundary_signal 驱动边界调整候选；反复出现、无法归入现有结构的锚点形成候选 Concept / Domain，累积验证后晋升；支持拆分与合并，挂载的链接、KPP 和 Wiki 标记随概念迁移；所有演化动作经 Learning Result 记录，可回滚。

### 12. Agent 接入层与全自动晋升

依据 `design.md` 第 8 节。知识大脑作为认知服务开放：提供领域记忆激活、来源证据、认知路由、临时认知模型、冲突检测、Learning Event 记录与学习建议；HTTP API，按领域边界授权，不暴露整库为通用 RAG；Agent 使用结果产生 Learning Event 回流。不做任务调度、工具运行时、多 Agent 协作协议、权限沙箱。

ActivationLink 晋升转为自动，但**按风险分层，不是无条件全自动**——采用类信号只证明链路自洽，不证明结论正确，无门槛的自动晋升会稳定强化"回答看似合理、用户未纠正、结论错误"的路径：

```text
常规领域：晋升全自动，人工退化为可选审计；
高风险 Domain：晋升保留前置门槛——人工确认或查证模式通过，二选一；
灰度：新晋升的 verified 链接先以低权重 / 影子命中方式观察 N 次，
      表现达标后才获得正式召回权重；
回滚：晋升后 fail 率超过阈值自动降回 weakened，写 Learning Result；
真值来源：错误强化率依赖金标题集（见 V2 readme）上的周期性人工
      抽样审计与 Agent 任务结果反馈——这部分成本无法全自动消除，
      设计上如实承认，不假装闭环可以自我校准。
```

## 学习回流（V3 → V1 / V2）

V3 是材料成熟的信号来源，回流通道必须在早期阶段就打通：

```text
槽位角色信号：  某 KP / Claim 在 Working Model 中实际承担的角色及其有效性
                → 写入链接的 learned 字段并更新置信度，
                  覆盖 declared / compiled 的低置信起点；
关系候选：      不同材料的 KP 填入同一模式槽位时显现的归属与先后关系
                → 跨多次事件稳定复现才沉淀为 KPN 长期关系；
模式误配：      mode_misjudge 事件修正 intent 映射与 KPP 挂载；
表达层信号：    Claim 被采用 / 被纠正、页面直答后被追问或回落
                → 驱动 V2 重编译候选与页面拆分 / 合并 / 降级；
实践路径：      深想结构反复有效 → 提炼、验证、沉淀（能力 7）。
```

## 实现顺序

四个阶段，每阶段可独立交付验证：

```text
阶段一：深度思考能力
  1. 认知路由（三路径 + 升级信号 + 处理上限）
  2. Service / Agent 架构重组
  3. KPP 在线执行（前置识别 + 槽位驱动检索 + 定向证据挖掘）
  4. Working Model + RP 执行 + 质量检查 + 槽位角色信号回流
  —— 交付：复杂问题回答质量在金标题集上优于 V1 deep 路径基线
           （指标与阈值见模块文档）；词汇鸿沟类问题可正确召回作答；
           推理输入全部经材料访问契约，不解析页面文本

阶段二：证据可靠性
  5. 查证模式与外部证据
  6. 冲突检测模式（含链接 conflicted 状态启用）
  7. 生命周期证据链传导补齐（状态沿用 3 状态，不扩展）
  —— 交付：高时效 / 高冲突问题给出带来源与边界的可靠回答

阶段三：经验与视角
  8. 实践路径提炼、验证与经验路径
  9. 反思学习
  10. 认知视角在线化（声明 / 推断 + 视角化学习累积）
  —— 交付：同类复杂问题第二次处理明显快于第一次

阶段四：沉淀与开放
  11. Wiki 编译完整版（四种新页面类型 + 自动重编译候选 + 视角化编译）
  12. Concept / Domain 演化完整版
  13. Agent 接入层 + ActivationLink 全自动晋升 + KPP 模式库演化
  —— 交付：知识体系可读可维护，可被外部 Agent 消费
```

## 数据与存储变化（概要）

```text
新增
  practice_paths       实践路径（模板内容、适用边界、状态、验证记录）
  external_evidences   外部证据记录（必选持久化：URL、快照 / 版本时间、
                       发布者、来源等级、抓取时间、有效期、引用片段、
                       适用范围）

扩展
  activation_links     conflicted 状态启用；learned 来源字段开始写入

                       mode_misjudge / slot_gap / relation_candidate 等

```

具体 schema 在各模块实现文档（`docs/impl/v3/<module>.md`）中定义。

## V3 成功标准

```text
按需思考：    简单问题不进深想，复杂问题不停留浅检索；
              路由准确率在金标题集上达到模块文档阈值
              （先测基线后定阈值，见 V2 readme），误判可被反思学习捕获；
材料消费：    深想的推理输入全部经 V2 材料访问契约获取
              （静态认知包 + 动态槽位证据解析），无绕过契约的检索路径，
              无从页面文本临场解析结论的路径；
深度回答：    设计 / 判断 / 决策类问题输出含变量、正反证据、推理路径和
              边界的结构化回答；证据充分性以必需槽位填充率判定，
              空槽位显式呈现为缺口而非被内容凑满；
结构先行：    词汇鸿沟类问题经槽位扩展正确召回；跨视角提问经槽位重组
              正确作答，且每格内容可回链原文；
证据可靠：    高时效问题附外部查证来源；矛盾证据输出条件化结论；
              过期知识不进入当前回答；
经验复用：    同类复杂问题反复处理后形成实践路径，再次出现时
              处理成本与延迟较深想完整流程下降，降幅达到模块文档阈值；
视角分化：    同一知识库在两个视角下形成可观察的不同激活路径
              和不同 Wiki 页面；
材料成熟：    链接的 learned 字段随使用持续覆盖 declared / compiled
              起点，低置信声明可被使用信号验证或否定；
自主学习：    常规领域链接全生命周期无需人工介入，人工仅做审计；
              高风险领域晋升门槛、灰度与回滚机制可观察生效；
              错误强化率经金标题集抽样审计不超过模块文档阈值；
体系沉淀：    Wiki 页面覆盖主要高频主题，结论均可回链证据，
              底层变化能触发重编译；
Agent 可用：  外部 Agent 完成「激活记忆 → 获取证据 → 记录学习事件」
              的完整调用，且其使用反哺学习；
边界守住：    Trace 仍只记录学习事件；Study 仍只调整长期记忆；
              不新增知识存储层；系统数据增长以 verified 链接质量
              和 Wiki 覆盖率衡量，而非存储量。
```
