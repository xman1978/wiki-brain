# 历史会话删除确认框设计

## 背景

当前 UI 中历史会话列表的删除按钮会直接调用删除接口，缺少二次确认，存在误删风险。

## 目标

在删除历史会话前弹出确认对话框；用户确认后才执行删除，取消则不做任何操作。

## 方案

复用 `web/index.html` 中现有的 `showConfirm()` 页面内确认弹窗能力，不新增新的弹窗组件或状态结构。

删除入口仍保持在历史会话列表项右侧的删除按钮：

- 点击删除按钮时先阻止事件冒泡，避免触发会话切换
- 调用 `showConfirm('确认删除该历史会话？')`
- 仅在用户确认后继续执行原有 `DELETE /sessions/{id}` 流程
- 删除成功后的会话刷新、当前会话回退/新建逻辑保持不变

## 不做的事

- 不调整删除后的跳转逻辑
- 不展示更复杂的会话标题、额外警告或多级确认
- 不顺带替换页面中其他仍使用原生 `confirm()` 的位置

## 测试与验证

- 增加一个针对 `web/index.html` 的静态回归检查，确认历史会话删除路径使用 `showConfirm()`
- 手动验证：
  - 点击删除按钮会先弹出确认框
  - 点击取消不会删除会话
  - 点击确定会删除会话
  - 删除当前会话后的现有回退逻辑仍正常
