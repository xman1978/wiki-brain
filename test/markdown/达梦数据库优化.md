## 5.3. 解决报错“语句句柄个数超过上限或系统内存不足”
修改达梦数据库参数 dm.ini

| 参数 | 建议值 | 说明 |
| --- | --- | --- |
| MAX_SESSION_STATEMENT | 20000 | 每个会话打开的最大句柄数 |


由于程序很多地方存在不关闭 statement 的问题，导致达梦数据库报错“语句句柄个数超过上限或系统内存不足”。为避免此问题，建议从程序入手根本解决。
可以用下列语句查询会话打开的句柄：
select session#, sql_str from v$open_stmt
where sql_str is not null order by sql_str;
select session#, count(*) cnt from v$open_stmt
group by session# order by cnt desc;
## 5.4. 内存参数

SELECT /*+OPTIMIZER_OR_NBEXP(2)*/
CATE.MODULE moduleCode,
CATE.CATEGORY_CODE categoryCode,
HIP.EXT_PROCESSCODE processCode,
count(RES.ID_) taskNum,
CATE.CATEGORY_NAME categoryName,
DEFINE.PROCESS_NAME processName,
DEFINE.PROCESS_ICON processIcon,
DEFINE.PROCESS_ICON_COLOR processIconColor
FROM FLEXOFFICE.ACT_RU_TASK RES
INNER JOIN FLEXOFFICE.ACT_HI_PROCINST HIP
ON HIP.ID_ = RES.PROC_INST_ID_
INNER JOIN FLEXOFFICE.BPM_PROCESS_DEFINE DEFINE
ON DEFINE.PROCESS_CODE = HIP.EXT_PROCESSCODE
INNER JOIN FLEXOFFICE.BPM_CATEGORY CATE
ON CATE.ID = DEFINE.CATEGORY_ID
LEFT JOIN FLEXOFFICE.ACT_RU_IDENTITYLINK I
ON I.TASK_ID_ = RES.ID_
WHERE RES.TENANT_ID_ = ?
AND (RES.EXT_HIDE_UNDOLIST IS NULL OR RES.EXT_HIDE_UNDOLIST = '')
AND ((RES.ASSIGNEE_ = ?) OR (RES.ASSIGNEE_ IS NULL AND
I.TYPE_ = 'candidate' AND (I.USER_ID_ = ?)))
AND CATE.MODULE in (?)
GROUP BY CATE.MODULE,
CATE.CATEGORY_CODE,
HIP.EXT_PROCESSCODE,
CATE.CATEGORY_NAME,
DEFINE.PROCESS_NAME,
DEFINE.PROCESS_ICON,
DEFINE.PROCESS_ICON_COLOR
ORDER BY CATE.MODULE, CATE.CATEGORY_CODE, HIP.EXT_PROCESSCODE
