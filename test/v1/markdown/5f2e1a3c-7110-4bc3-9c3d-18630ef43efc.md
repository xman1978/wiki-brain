## Oracle RAC 问题汇总

1. VKTM 进程导致 CPU 占用高
现象
Oracle 11g RAC 引入了 VKTM 进程，此进程存在于 ASM 和 ORACLE 实例，负责时钟时间（1 秒更新一次）和参考时间服务（每 20ms 更新一次，且在 VKTM 进程处于高优先级的情况下可用），该参考时间用于各种基于时间的度量。
在某些环境下，特别在虚拟化（vmware、virtualbox 等）环境下，VKTM 进程会消耗过多的 cpu 资源。在 linux 环境下可用以下命令检查，
ps H -eo pid,ppid,tid,%cpu,user,cmd --sort=%cpu | tail -5

处理
在非生成环境下，可通过修改 _high_priority_processes 隐藏函数让 VKTM 进程不运行在高优先级下，从而降低 CPU 资源的占用。但是这样也会导致参考时间不可用，所以不建议用于生产环境。
```
$ su - oracle
$ sqlplus / as sysdba
SQL> alter system set "_high_priority_processes"='LMS*' scope=spfile;
$ su – grid
$ sqlplus / as sysasm
SQL> alter system set "_high_priority_processes"='LMS*' scope=spfile;
```

2. oracle 进程粘连位导致客户端无法连接
现象
Weblogic 通过SCAN IP 地址连接 Oracle RAC，发现以下报错：
weblogic.common.ResourceException: weblogic.common.ResourceException: Could not create pool connection. The DBMS driver exception was:IO Error: Got minus one from a read call

通过 sqlplus 命令检查 RAC 内两个实例的连接性，发现其中一个实例无法通过 IP 地址连接，报以下错误：
```
TNS-12518: TNS:listener could not hand off client connection
TNS-12547: TNS:lost contact
TNS-12560: TNS:protocol adapter error
TNS-00517: Lost contact
Linux Error: 32: Broken pipe
```

打开侦听的trace，在 trace file 中可发现以下报错，
nsglhe:Direct handoff errors: ns=12547, ns2=12560

处理
参看 metalink ID 1069517.1 文档，此问题是由于 oracle 程序文件缺失粘连位导致，
```
$ ls -l /u01/app/oracle/product/11.2.0/db/bin/oracle
-rwxrws--x 1 oracle asmadmin 222235870 Oct  3 12:46 oracle
```

重新赋予粘连位，问题解决
$ chmod u+s /u01/app/oracle/product/11.2.0/db/bin/oracle
